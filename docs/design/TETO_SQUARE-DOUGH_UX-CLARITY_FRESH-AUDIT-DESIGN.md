## 0. 結論（先に）

1. 「簡単すぎる」と「わかりづらい」は**別々の原因**で、実測で両方再現した。
   - **簡単すぎる**: 画面幅の約 3.5 倍（約 1,000px・約 1 秒）の 1 本のジグザグで **STEP 1 と STEP 2 が同時に終わり**、「次へ」が有効になる。STEP 2（押して平らにする）は一度も触らずに済む。短いドラッグ 1 回では進めない（§3.4）。
   - **わかりづらい**: UI が教える通りに「四隅へ 4 回なぞる」と、**四隅 4/4 の ✓ が全部点いたのに STEP 1 が終わらず**（ひろがり 75.5%・目標 95%）、**矢印ヒントは全部消え**、文言は「四隅まで伸ばそう（四隅 4/4）」のまま。次に何をするかが画面のどこにも出ない（§3.3、スクリーンショット）。
2. `SquareTargetGuide` は **SAUCE 工程の「ここまで塗る」ガイド**で、DOUGH 工程には出ていない。DOUGH の目標表示は既に別物（四隅マーク・ドラッグ矢印・ひろがり/なめらかゲージ・STEP 表示）が実装済み。**案 A（目標ガイド＋四隅の方向マーカー）は大半が既存**で、足りないのは「四隅到達後の次の方向」だけ。
3. **推奨（最小案）**: 四隅到達後〜STEP 1 完了までの**案内だけを足す**（A の不足分 + B の既存ゲージの活用）。判定・採点・保存・閾値は一切変えない。難易度（簡単すぎる）は**この最小案では動かさない**。難易度は §5 の Owner 判断（C 案 / 閾値）として分離する。
4. 先行資料にも「簡単すぎる」は既知: `TETO_SQUARE-DOUGH_C_Corner-Drag_Result.md` Open item 1（「掃くプレイヤーは STEP 2 が始まる前に終わる。evenness 値の選択であり未変更」）。本監査は、その後の #558（自然変形）後でも成り立つことを数値で再確認し、Owner の体感と結びつけた。

### 3.2 実コンポーネント（配信ビルド `c98d957`、実ポインタ、390×844 と 360×800 で同一の値）

- **一筆ジグザグ（7 点の 1 ストローク）** → `data-step=2, data-complete=true`、ひろがり 0.980・なめらか度 0.743、「次へ」有効、目標文は「できあがり！」。

### 3.3 「わかりづらい」の具体的な原因（実測で確認）

1. 四隅 ✓ が 4 つ点灯した時点で STEP 1 は終わっていない（被覆率 95% が別条件）。✓ は「STEP 1 達成」と読める見た目。
2. 到達済みの隅の矢印が消えるため、**四隅到達後は矢印が 0 本**。次に伸ばす方向の手掛かりが盤面から消える。
3. 目標文が `四隅 4/4` のまま「四隅まで伸ばそう」で、状態と文言が矛盾する。
4. 残りは**天板の辺沿いの灰色の欠け**（スクリーンショット `stuck-after-4-corners-390x844.png`）。ゲージは 75.5%/目標 95% と数値では正しく出ているが、**どこを埋めればよいかが盤面に出ない**。#536 の受け入れ条件「完成条件を満たさない理由が視覚的に分かる（どこが薄い・厚いか）。テキストの説明に頼らない」は、この状態については未達。
5. 加えて、隅 ✓ は距離の 70% 地点で点く（ひろがりはまだ 61%）。「隅まで届いた」の体感が早く、残りの 95% への距離感が出ない。

→ 先行資料 Result C の計測（掃引＋隅 4 本、greedy edge pulls）は被覆を稼ぐ操作を前提にしており、**素直に隅だけを 4 回なぞると 75% で止まる**ことと、その時の矢印消失・文言の矛盾には触れていない（Result C / B2 を `hint`・`矢印`・`gap`・`stuck` で検索して確認）。

### 3.4 「短いドラッグだけで進行するか」への回答

- **進行しない**: 30px 単発で +2.1pt、隅 0。STEP 1 の完了にはひろがり 95% が必要で、放射状（隅への 4 本）だけでは 75% で止まる。
- **進行するのは「面を覆う」操作**。最小は 3 往復（約 350% ≈ 390×844 で約 1,015px、360×800 で約 960px。連続 1 筆で約 1 秒）。この 1 筆で STEP 2 も同時に満たす（なめらか度 0.744 > 0.6）。
- 原因は 2 つ。(a) ドラッグが厚みを周囲へ流す（#558 `flowAround`）ため、覆うだけでなめらか度が高くなる。(b) なめらか度の定義は未被覆セルを 0 とみなすので、被覆が 100% に近づくと自動的に上がり、**丁寧に整えた生地と一筆の走り書きを区別できない**。閾値を 0.8 にしても 4 往復以上の走り書きは通る（0.84–0.94）。
- 注意: 実際の Owner の指の軌跡ログは無い（HV は動画。`?diag=1` は軌跡を出力しない）。上記は合成軌跡。**実軌跡は次回 HV で `?diag=1` の記録を使えば取れる**が、共有 Preview の更新が要る（Owner 承認事項）。

### 推奨する最小案: 「A の不足分 + B の盤面表示」（案 AB-min）

判定・採点・保存形式・閾値・ゲージ・ジェスチャを一切変えず、**導出して描くだけ**にする。

1. **四隅到達後の方向ヒント**: STEP 1 かつ「4 隅到達・ひろがり未達」の間、**未被覆セルの大きい塊**に向けて破線矢印（または塊の縁取り）を最大 2〜3 本出す。位置は dough の被覆から導出（保存しない）。既存の `hints` の仕組み（生地の縁→目標点の矢印）を再利用し、「目標点」を隅マークから未被覆塊の重心にする。
2. **目標文の差し替え**（行は増やさない）: 4/4 到達・ひろがり未達のときだけ「すき間をうめよう（ひろがり 75% → 95%）」。0〜3 隅は現行のまま。「次へ」下の補足行も同様に 1 行差し替え。
3. **隅 ✓ の意味づけ**: ✓ 点灯後も「STEP 1 はまだ」と分かるように、STEP 帯の STEP 1 に進捗（既存のひろがり値）を併記するか、✓ をひろがり 95% 到達まで半透明にする（どちらか 1 つ。Owner HV で選ぶ）。
4. 採用しないもの: アウトライン（情報ゼロ）、新しいゲージ（既存と重複）、`SquareTargetGuide` の DOUGH 流用、盤面外の行追加、C 案。

**簡単すぎる**に対する扱い: AB-min では**動かさない**（理解しやすさを先に直し、その後で難易度を議論する、という Owner 方針どおり）。ただし AB-min は「何をすれば終わるか」を明確にするので、**簡単さの体感はむしろ増す可能性がある**。難易度の選択肢は §6 に分離して提示する。

## 6. Owner 判断が要る点（実装前に確認）

1. **「簡単すぎる」の意味**: (a) 一筆で STEP 2 まで終わる（実測 §3.1）／(b) 隅 ✓ が早く点く／(c) 別の体感 のどれか。動画では判別できなかった。
2. 難易度を扱う場合の選択肢（いずれも**進行条件・閾値の変更**なので別承認）:
   - 値のみ: `SQUARE_COMPLETE_EVENNESS_MIN`（0.6）。ただし §3.4 のとおり 0.8 でも 4 往復以上の走り書きは通る。単独では効果が限定的。
   - ドラッグが厚みを流す量（`DRAG_FLOW_RATE`/`RADIUS`、#558）を弱め、STEP 2 の押す操作を意味のあるものに戻す。#558 の自然変形（Owner HV 済み）とのトレードオフ。
   - C 案（形の完成度評価）。指標の設計から必要。D4（採点不変）との整合を Owner が決める。
3. ✓ の扱い（§5 の 3 項）の A/B 選択。

## 8. 再現手順（read-only）

- 純関数: `npx vite-node <script>.ts`（`npm ci` 後）。`createInitialSquareDough` → `dragAlong`（`squareDoughDrag.ts`）→ `squareDoughProgress`。ストローク列は §3.1 の表のとおり（放射状は中心 (50,50) → `CORNER_MARKS` × r、ジグザグは x=12→88 を y=20/50/80）。
- 実コンポーネント: 配信ビルド `c98d957`（`?panSwitch=open`）を `vite build --base=/teto-pizza-game-preview/` 相当で配信し、「ピザを作る」→「レシピ発見へ」→ □ を選択。`.square-dough-layer` の boundingBox 上でポインタ操作し、`data-step / data-corners / data-coverage / data-evenness / data-complete` と `square-drag-hints` の本数を読む。
