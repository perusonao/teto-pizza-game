## 3. プレイヤーの操作

### 3.1 流れ

```
TOPPING 工程で beef の chip を選ぶ
   │  （対象: 炒め対象 ∧ 専用 SVG あり ∧ 在庫あり ∧ まだ炒めていない）
   ▼
[OFFERED] ステージ下の空き帯に「🍳 炒める」ピルが出る
   │  タップ                                   （出さない／押さない → 今までどおり配置できる）
   ▼
[PAN] ステージの内側がフライパン画面になる（dock・bar は動かない）
   │  どこでも 3 回タップ（トスの動作）
   │  ×／別の操作 → 中止（何も残らない）
   ▼
[DONE] 「ジュッ！」の演出（約 0.7 秒）→ 自動で閉じる
   ▼
ステージに戻る。ピルは「✓ 炒め済み」の表示（押せない）に変わる
   ▼
牛肉の配置（従来どおりのタップ）→ 盤面の牛肉は「炒め済み」の見た目
```

### 3.2 操作の詳細（設計値）

| 項目 | 仕様 |
|---|---|
| 開始 | ピルをタップ。ピルは beef が選択されている間だけ出る。他の食材を選ぶと消える |
| トス | パン画面の**どこでもタップ**で 1 回（最低でもパン円の直径 230px 以上が当たり判定）。タップごとに牛肉が跳ね、湯気が増え、肉の色が 1/3 ずつ進む |
| 回数 | **3 回で完了**（P-1） |
| 速さの制約 | **無し**。ゆっくりでも完了する。**失敗状態・時間切れ・やり直しの強制なし** |
| 連打の扱い | 120ms 未満の連続入力は 1 回として扱う（iOS のダブルタップ誤検出と二重カウントの防止） |
| 完了 | 3 回目で「ジュッ！」。約 0.7 秒後に自動で閉じる。**確認ボタンは無い** |
| 中止 | ×（44×44）、または画面外の操作。中止すると**何も残らない**（状態を変えない） |
| 取り消し | 炒め済みを「戻す」操作は**作らない**（影響が見た目だけで、戻す価値が小さい）。`RESET_PIZZA`（やり直す）では炒め済みも消える |
| 既に置いた牛 | 炒めたとき、**既に盤面にある beef もまとめて炒め済みの見た目になる**（食材単位のため。P-4） |
| 所要時間（見込み） | 最短 約 1.5 秒、通常 3〜5 秒。受け入れ基準は **≤ 8 秒**（実測は HV） |

### 3.3 モード別

| モード | 挙動 |
|---|---|
| Guided | 有効（rendang-pizza でも、beef を選んだときだけピルが出る） |
| Free Cooking／Research | 有効。**炒め可否は食材の id だけで決まり、レシピ・標的で変わらない**ため、標的の手がかりにならない |
| Lunch Rush | **無効**（ピルを出さない。reducer も拒否）。rendang は元々 `lunchRush: false` |
| Dinner | **無効**（reducer が拒否） |

### 3.4 アクセシビリティ・入力

- ピルとパン画面は `button`。キーボードは Enter / Space で 1 トス（タップと同じ）。
- 反応は `pointerdown` で即時（遅延なし）。`touch-action: manipulation` でダブルタップ拡大を抑える。
- 「動きを減らす」設定では、跳ねる・湯気をやめ、色の段階変化とテキスト（「1/3」「2/3」「3/3」）だけにする。
- 画面の読み上げ: 開始時「フライパンです。3 回タップして炒めます」、各トスで「1 / 3」、完了で「炒め済み」。

## 4. 調理前後の見た目

### 4.1 段階ごとの見た目

| 段階 | 見た目 | 備考 |
|---|---|---|
| 炒める前（トレイの chip・盤面） | **生っぽい赤の牛肉**（SVG の `doneness = 0`） | 現行の見た目の置き換えは Line C の SVG による。本機能の既定値 |
| パン画面の途中 | 3 トスで `doneness` が 0 → 1/3 → 2/3 → 1。湯気の量が増える | パン画面の中だけの絵。ピザ盤面とは別に描く |
| 炒め済み（PREPARE の盤面） | **焼き目のついた茶色、つやのあるハイライト**（`doneness = 1`） | 炒め済みの食材の全ピースに適用 |
| 焼成後 | 炒め済みの方が深い色のまま。未炒めは現行の焼き曲線のまま | 焼き曲線の差は小さいので、**差の主役は SVG の色**（§4.3） |
| CUT | 半分ピースも同じ見た目（同じ描画経路） | 調査 Result §3.1 |
| RESULT | プレイヤーのピザは炒め済みの見た目。図鑑サムネイル・Reference 見本は**既定の見た目のまま** | 見本と見た目が違う点は HV で確認（P-5） |

### 4.2 「やらない」場合

**未炒めの見た目は、現行（#691 の SVG 導入後は SVG の `doneness = 0` ＝ #691 の HV 合格色）のまま。** 炒めないことによる減点・警告・見た目の劣化は**作らない**。

### 4.3 焼き色の連動（設計値）

- 既存の `toppingVisualFrame(heat)` は「ちょうど」でほぼ変化しない（sepia 0.08）。炒め済みに +0.4〜0.9 の熱オフセットを足しても差は小さく、**この曲線だけでは任意操作の報酬にならない**。
- よって**報酬の主役は SVG の色**（`doneness` による生→焼き目）。焼き曲線のオフセットは補助で、初期値は **0**（足さない）。HV で足りなければ調整（P-7）。
- 二重に暗くならないよう、SVG の色は「炒め済み」で確定し、焼成フィルターは既存の曲線のままにする。

### 4.4 `beef-slices` が本機能に要求する契約（SVG 自体は Line C 担当。第 5 回で #691 の現状に合わせて更新）

> **現状（2026-10-28）:** `"beef-slices"` と beef の `pieceVisual` は **#691（open）が追加する**。ただし #691 の `BeefSlices` は**色が固定値**で、下の「焼き加減の入力」「つや」の契約（CSS 変数）は**未実装**。変数化は **#691 merge 後に本機能の実装 PR（S3）で行う**（§18.1 O-3）。#691 には変更を依頼しない。

| 項目 | 要求 |
|---|---|
| 識別 | `DedicatedIngredientVisual` に `"beef-slices"` を追加し、beef に `pieceVisual` を設定する（`ingredients.ts`、`IngredientGlyph.tsx`）。**→ #691 が実施。本機能は `ingredients.ts` を触らない** |
| 焼き加減の入力 | **CSS 変数 3 つ**: `--beef-lean`（赤身）、`--beef-fat`（脂）、`--beef-edge`（縁）。TypeScript が `doneness`（0〜1）から線形補間して渡す。`color-mix()` は使わない（iOS Safari の古い版への配慮） |
| 既定値 | 変数が未指定のときは**生の色**で描く（`doneness = 0`）。既存の呼び出し元（図鑑・Reference・トレイ）は無変更で動く |
| つや | 炒め済みのときだけ表示する 1 枚のハイライト（`--beef-gloss` の不透明度） |
| 色 | **生（`doneness = 0`）は #691 の HV 合格色を採用する**（§18.1 O-4、§18.3 の一覧）。第 4 回までの暫定「生」色（赤身 `#c8554f` / 脂 `#f1d9c9` / 縁 `#8a2f2c`）は**廃止**。**炒め済みの目標色は provisional のまま**（赤身 `#7a4226` / 脂 `#d9b48a` / 縁 `#3d2314`。Style Lock と iPhone HV で確定） |
| 識別の注意 | 生の赤はペパロニ・生ハム、焼き目の茶はソーセージ・ベーコンと近い。20px 級で**他の肉と区別できる形**（薄切りのリボン 2〜3 枚）であること（PR-2 設計の `beef-slices` 案と整合） |
| 休眠の保証 | **この SVG が無い間、本機能は出ない**（§5.2 の対象判定） |

## 6. 楽しさの設計

### 6.1 何が楽しさを作るか（仮説）

| 要素 | 仕様 | 狙い |
|---|---|---|
| 1 秒で伝わる | ピルの文言と絵だけで内容が分かる。説明文は 1 行 | 学習コスト 0 |
| 手応え（視覚） | タップごとに牛肉が跳ね、湯気が増え、色が進む。完了で「ジュッ！」＋短い光 | 音・振動が無いため、**視覚の反応の速さと量**がすべて |
| 目に見える進捗 | 3 つの印（●●●）が埋まる。肉の色が 3 段階で変わる | 「あと何回か」が分かる |
| 変化が盤面に残る | 炒め済みの牛が盤面・焼成後・RESULT まで残る | **やった甲斐の中心** |
| 失敗しない | 遅くても完了。中止しても何も失わない | 気軽に試せる |
| 任意 | 押さなくてよい | 「面倒」を避ける |

### 6.2 つまらなくなる恐れと対策

| 恐れ | 対策 |
|---|---|
| 採点に効かないので「ただの作業」に感じる | 任意にする。変化が盤面に残る。HV で「やらなくても困らない／やると嬉しい」の**両方が成り立つか**を見る |
| 3 回タップが単調 | 演出を重ねる（跳ね・湯気・色）。**P-6: タイミングの演出（拍に合うとナイス）を足すかは HV 後に判断** |
| 毎回やるのが面倒 | 1 ラウンド 1 回まで（食材単位）。≤ 8 秒 |
| 牛の絵が地味で変化が見えない | **SVG が前提**（Line C）。この仕様は SVG が無ければ出ない |

### 6.3 Human Verification の観点（Owner 判定）

390×844 の動画＋前後スクリーンショット（`docs/reports/screenshots/<task-name>/`）に加え、**撤回の判定は iPhone 実機 HV で行う（Owner 決定 P-10）**。Owner が次を判定する。

1. やりたくなるか（ピルに気づくか、押したくなるか）。
2. 3〜5 秒が「楽しい」か「長い」か。
3. 炒め済みの牛が**盤面で一目で分かる**か（20px 級・焼成後）。
4. やらなかったときに損をした気がしないか。
5. 他の肉（ペパロニ・ソーセージ・ベーコン）と見分けがつくか。

**合否基準（Owner 決定 P-10、§16.2）:** 通常操作 8 秒以内を目安に、視覚反応・視認性・誤操作・1 画面表示・既存機能との互換性を iPhone 実機 HV で評価する。**重大な誤操作・進行不能・保存不整合は不合格。** 楽しさ不足は演出の修正を 1 回まで行い、改善しなければ公開を見送る。SVG が無い／判別できない場合は機能が出ない（§5.2）。
