### Q7 — コホート文字と Recipe Batch Validator の例外
- 現状: ハモンセラーノは「最後に解禁される有限材料＝ルッコラ（step 33）」のコホートの**唯一の**メンバー。Research のラベルは文字なし（「？？？ピザ（ルッコラ）」）。
- Pinsa を足すと同じコホートに 2 件入り、**ラベルに文字が付く**。導出（`id = pinsa-romana`、`opaqueHash` 順）: Pinsa = **A**、ハモンセラーノ = **B**。文字は id のハッシュで決まるので、最終 id で再導出する（固定しない）。
- プレイヤーへの影響:
  - ルッコラを持っていてハモンセラーノ未発見の人は、Research のラベルが「？？？ピザ（ルッコラ）」から「？？？ピザ A／B（ルッコラ）」に**変わる**。Research の候補は 1 → 2 件になり、HOME の「レシピ発見」の直行（候補 1 件のとき）が**選択画面に変わる**（PK-14: HOME / Pizza Select / Hint シートのテストを一覧化して更新）。
  - A と B は**食材集合が同一**で、○×の行も同じ。標準生地で作ると必ずハモンセラーノになるので、Pinsa は技法（生地チップ）の発見が前提になる。発見の手がかりは Dex の調理法欄のなぞかけ（承認済み）と G2 のみ（設計 §13）。
  - 解禁タイミング: 技法の affordance は材料の最大 unlock step = **33**。**credited が 33 以上の既存プレイヤーは、P3 の反映と同時に**「ほかの生地」のチップ（Free Cooking / Research の生地工程）と Dex の調理法欄のなぞかけが現れる。Preview で見た表示が本番で現れる瞬間になる。
- 推奨: **許容する**（OD-544-4/5、marinara と同形）。Recipe Batch Validator の「新レシピは既存コホートに入らない」には、**名前付きの allowlist 例外**として `pinsa-romana` を追加する（暗黙の緩和にしない）。
- 止めるもの: P3。**必要な Owner 判断**: 許容するか、許容する場合の例外の扱い。
