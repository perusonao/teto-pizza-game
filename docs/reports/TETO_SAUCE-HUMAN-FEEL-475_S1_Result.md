## 1. 原因（Step 0 の結論）と変更

Step 0（Issue #475 のコメント）で、階段状・角張った縁の**主因は、表示用の密度場が 16×16 の正方形カーネル**（1 deposit = 3×3 セルのブラシ＋3×3 ブラー 2 回）でできていることと確定した。canvas の解像度・補間品質・DPR・CSS ブラー・焼成フィルタはほぼ無関係で、表示サイズが大きいほど階段も比例して大きく見える（増幅要因）。

変更:

- 新規 `src/logic/sauceDisplay.ts`: 各 deposit を**放射対称ガウス**で **64×64 の表示用密度**に直接足し、**既存のアルファ曲線（`sauceDensityToAlpha`、床 0.46・上限 0.93）をそのまま**使って画素化する。カーネル表（サブピクセル位相 4×4）とシルエットマスクをキャッシュ。
- `src/components/SauceHeatmapCanvas.tsx`: 描画を上記に切り替え。**CSS のブラー・フィルタ、canvas 200px は不変**。64×64 のステージング canvas は共有して再利用（毎回の生成が描画本体より高コストだったため）。
- `src/logic/sauceField.ts`: **追加のみ**（`SAUCE_DISPLAY_MIN_VISIBLE_VALUE` と `sauceDensityToAlpha` の再エクスポート 8 行）。`buildSauceField` / `computeSauceMetrics` / `smoothSauceFieldForDisplay` / `sauceFieldToRgbaPixels` は無変更で、採点用 16×16 データはそのまま。

校正値（`sauceDisplay.ts` に定数として固定。変えると見た目が変わるので、extent テストを再実行すること）:

## 3. 性能

- 条件（Step 0 と同じ）: Chromium、CDP の CPU 4× スロットリング、1 回の再描画 = `SauceHeatmapCanvas` の effect 本体（密度場＋画素化＋canvas 描画）、8 反復、各反復で main と branch を**交互**に実行。計測用ハーネスはリポジトリに入れていない。headless のソフトウェア描画のため、**実機の GPU 合成コストは測れていない**。
- 2 通りで計測: **[stream]** ＝ 実際のゲームの動き（ストロークが 1 tick ごとに deposit を 1 つ足して再描画。1 反復 = 1 ストローク全体）、**[miss]** ＝ 増分キャッシュを使えない最悪ケース（毎回、最初の deposit を変えて 60 回の全再構築）。
- 3 回の独立した実行の結果（p95、Δ = branch − main、ms）:

| ケース | [stream] Δp95（3 回） | [miss] Δp95（3 回） | branch の p95 平均（範囲） | 単発の最悪 p95 |
|---|---|---|---|---:|
| 渦巻き | +0.16 / −0.89 / +0.09 | +0.03 / +0.94 / +0.85 | 1.9〜3.9 | 6.4 |
| 中央長押し | −1.74 / −0.56 / −1.25 | −0.83 / −0.20 / +0.78 | 1.7〜4.2 | 5.0 |
| リング | −0.28 / +0.11 / +0.27 | −0.37 / −0.85 / −0.64 | 2.0〜2.8 | 5.8 |
| 理想フィクスチャ | −1.16 / −1.25 / −1.22 | +0.28 / −0.22 / +0.62 | 1.3〜3.5 | 5.7 |

- 判定: **全ケースで Δp95 ≤ +0.94ms（基準 +2ms）、最悪の単発でも 6.4ms（基準 8ms）**。
- ノイズ: main の p95 の標準偏差は 0.5〜2.6ms と大きい（スロットル下の単発の外れ値）。判定は 3 回の実行の平均 p95 の差で行い、単発の最悪も併記した。
- **最初の版は不合格だった**（Δp95 +2.2〜+4.4ms、単発 9〜12ms）。内訳計測で、毎回の canvas / ImageData 生成（約 1.4ms）と密度の再加算が支配的と分かり、(1) ステージング canvas の共有、(2) 前回の deposit 列の続きなら差分だけ加算する増分キャッシュ（結果は新規構築とバイト一致）、(3) 行ごとに縁帯の判定を外す内側ループ、(4) カーネル半径 3.2σ→2.8σ（面積を再校正）で下げた。

## 6. 設計上の判断・既存挙動との差（Owner に見えるもの）

1. **縁帯（`SAUCE_TARGET_RADIUS` の外側）の扱い**: 旧表示は、ブラーが縁帯のセルを「16×16 の生の値」より濃くしないよう抑えていた（PR #28 の独立レビュー）。ガウスにはブラーの段がないため、**deposit からの距離で滑らかに弱める放射対称のテーパ（1.2〜2.8 セル）**に置き換えた。最初に試した「セル単位の可視判定のガード」は縁帯で階段を復活させたため採らなかった。単体テストで「どの固定 deposit でも、旧表示より遠くまでは塗らない」ことを固定している。
2. **可視しきい値 0.00404**（表示専用）: アルファ曲線は変えず、見かけの範囲を旧表示に合わせる校正。
3. **保持した点の位置**（注 B）。
4. 一度、縁帯のガードを入れたため渦巻きの粗さが 0.65% に戻る不具合があり、原因（ガード）を特定して外した。
