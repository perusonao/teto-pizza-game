## 1. V2 の問題（再確認）

| 問題 | 根拠 |
|---|---|
| 弱火だけで必ず 5/5 になる | 弱火の回収猶予は 2.9〜5.2 秒。初心者モデルでも 5/5 が 100%（§3.1） |
| 時間が評価されない | `verdict` は `rescuedCount` だけで決まり、`elapsedMs` は使われない |
| 開く順番が配置順と同じ | `opensAt` が index の昇順で、配置も 1→5 の順 |
| 大きさの差が小さい | 0.86 / 1.00 / 1.04 / 1.12 / 1.22 と連続的で、隣の貝との差は 4〜10%。見て区別できない |
| UX の小さな問題 | 縮んだ貝をタップしても反応がない、通知が残り続ける、フォーカス枠が出る、種類ボタンが 40px、結果画面で over と missed を見分けにくい |

**時間評価を足すだけでは解決しません。** V2 のパラメータのまま「5/5 かつ 6.8 秒以内なら★★★」にすると、
中級者モデルの強火のみで★★★が 89% になります。これでは強火一択に変わるだけです（§3.1 の下表）。
そのため V3 は、**評価方式とパラメータを同時に**変更します。

## 2. 推奨 V3 仕様（案）

### 2.1 評価 — 5/5 と最高評価を分ける

> **2026-11-05 改訂（試作時）:** 下表の「★★ = … または 4/5 かつ ≤ ★★★の時間」は採用しません。5/5 の遅い結果と 4/5 の速い結果が
> 同じ★★になってしまうためです。試作では「回収数を先に決め、時間は 5/5 の中だけを分ける」（4/5 は時間に関係なく★）としました。
> テスト `src/logic/steam/steamGameV3.grade.test.ts` で固定しています。詳細は `docs/reports/TETO_STEAM-V3_PROTOTYPE_Result.md` §2。

時間は「ふたをして蒸す」から「ふたを開ける」までを測ります。

| 評価 | 条件（あさり / ムール貝） | 意味 |
|---|---|---|
| **名人**（★★★＋バッジ） | 5/5 かつ ≤ 5.0 秒 / ≤ 5.4 秒 | 強火で攻めきった |
| **★★★** | 5/5 かつ ≤ 7.0 秒 / ≤ 7.4 秒 | 火加減の切替が上手い |
| **★★** | 5/5（時間超過）、または 4/5 かつ ≤ ★★★の時間 | 安全に全部救えた（弱火のみはここが上限） |
| **★** | 2〜4/5 | もう少し |
| **×** | 0〜1/5 | 次は開いたらすぐタップ |

- **弱火のみでは★★★に届きません（理論上の保証）。** 最後の貝が弱火で開くのは、あさりで 7.17 秒、ムール貝で
  7.67 秒です。反応時間を 0 秒としても、どちらも★★★の時間（7.0 / 7.4 秒）を超えます。
- 目標時間は開始前のメッセージに 1 回だけ表示します（「小さい貝から開くよ｜★3は7.0秒以内」）。プレイ中に減っていく
  カウントダウンや数値のゲージは**出しません**（Owner の方針「厳しい全体カウントダウンを避ける」と V2 の
  「常設の秒数ゲージなし」を維持）。結果画面には「★★★ 6.4秒・5/5」のように表示します。
- ゲーム本体の採点・保存・Pitz・Dex には反映しません（V1 / V2 と同じく Lab 内だけ）。

### 2.2 パラメータ

| | V2 | **V3 案** | 狙い |
|---|---|---|---|
| 進む速さ 弱火 / 強火（/秒） | 0.12 / 0.22 | **0.12 / 0.26** | 強火の時短効果を大きくする（約 2.2 倍） |
| 縮む速さ 弱火 / 強火（/秒） | 0.29 / 1.00 | **0.35 / 1.35** | 強火の猶予を約 0.7〜1.0 秒に絞る。弱火は約 2.6 秒以上を保つ |
| 開く直前の予兆 | なし | **あり**（`opensAt − 0.08` から貝が小刻みに揺れ、小さな泡が出る） | 強火で約 0.31 秒前、弱火で約 0.67 秒前に分かる |

### 2.3 開く順番 — 大きさで推測できるようにする

大きさを**3 段階**にはっきり分けます（見た目の倍率 0.85 / 1.05 / 1.25、隣の段階と約 20% の差）。
**小さい貝ほど早く開く**というルールを、開始前のメッセージで 1 回だけ伝えます。

| 種類 | 構成 | 開く順（opensAt / 縮むまでの耐性） | リズム |
|---|---|---|---|
| あさり | 小×2・中×2・大×1 | 小 .30/.95・小 .36/1.00 → 中 .55/1.10・中 .61/1.15 → 大 .86/1.30 | **ペア→ペア→1個** |
| ムール貝 | 小×1・中×2・大×2 | 小 .36/.90 → 中 .58/1.00・中 .64/1.05 → 大 .86/1.20・大 .92/1.25 | **1個→ペア→ペア** |

- 同じ大きさの 2 個は、強火で約 0.23 秒、弱火で約 0.5 秒の差で開きます。この「ペア」が火加減を切り替える
  きっかけになります。
- **配置は 4 パターンを順番に使います**（乱数なし・決定的）。値は 5 か所（上段 左・中・右、下段 左・右）に置く
  貝の開く順位です。

| 配置 | 上 左 | 上 中 | 上 右 | 下 左 | 下 右 | 1 番目に開く場所 |
|---|---:|---:|---:|---:|---:|---|
| L1 | 3 | 5 | 1 | 4 | 2 | 上 右 |
| L2 | 2 | 4 | 5 | 1 | 3 | 下 左 |
| L3 | 5 | 1 | 3 | 2 | 4 | 上 中 |
| L4 | 4 | 2 | 3 | 5 | 1 | 下 右 |

  「もう一度蒸す」で次の配置に進みます。「やり直す」では同じ配置のままです。どの配置も V2 の 1→5 の並びとは
  異なり、順番は**見て分かる大きさ**で決まるため、隠れた乱数にはなりません。
- 判断材料は見た目だけです（大きさ・予兆・橙色の光）。番号表示（1〜5）は配置の識別用として残しますが、
  開く順番とは関係しません。

### 2.4 火加減の切替が効くプレイ（あさり・中級者モデル、決定的トレース）

| 時刻 | 出来事 | 判断 |
|---:|---|---|
| 0.37 s | → 強火 | 何も開いていない間は強火で時短 |
| 1.35 / 1.58 s | 小a・小b が強火で開く（猶予 0.70 / 0.74 秒） | **ペアなので弱火へ** |
| 1.72 s | → 弱火 | 縮むのが遅くなる |
| 2.03 / 2.33 s | 小a・小b を回収 | 猶予の 64% / 40% を使った |
| 3.00 / 3.50 s | 中a・中b が弱火で開く（猶予 3.1 秒） | 余裕を持って回収 |
| 4.41 s | → 強火 | 残りは大 1 個なので攻める |
| 4.95 s | 大が開く（猶予 0.96 秒） → 弱火 → 5.62 s 回収 | |
| 6.83 s | ふたを開ける → **5/5・★★★（7.0 秒以内）** | |

同じ中級者が**弱火のみ**だと 8.97 秒で 5/5 → ★★、**強火のみ**だと時間は 5.53 秒ですが、ペアの 2 個目で猶予の
92% を使っています。ばらつきを入れたシミュレーションでは、5/5 になるのは 37% だけです（§3.2）。

ムール貝は「小が 1 個開いた後に中のペアが来る」ため、**中ペアが開く前に**弱火へ戻すのが鍵です。大きさで次の
ペアを読めるかどうかで差がつきます（強火に戻してすぐ中ペアが開くと、中b は猶予の 98% を使って間一髪でした）。

### 2.5 UX の改善（V2 HV で見つかった問題への対応）

| # | 問題 | V3 案 |
|---|---|---|
| U1 | 縮んだ貝をタップしても反応がない | over の貝もタップを受け付け、「縮んでしまった…次の貝を見よう」と表示（回収はできない） |
| U2 | 通知が残り続ける | 通知は約 1.2 秒で消え、状況に応じた案内（「橙色の貝をタップ」など）に戻る |
| U3 | タップした貝にフォーカス枠が出る | 貝の `pointerdown` で `preventDefault` してフォーカス移動を防ぐ。キーボード操作の `:focus-visible` は残す。iPhone Safari でも確認する |
| U4 | 種類ボタンが 40px | 44px にする（縦に 4px 増えるので、390×664 で 1 画面に収まるか試作で確認） |
| U5 | 結果画面で over と missed を見分けにくい | over＝茶色の縮んだ身＋しわ、missed＝灰色の点線の縁＋「?」。結果の案内文でも区別する |
| U6 | 開始前に火力を選べない | 待機中も弱火・強火を選べるようにし、選んだ火力で開始する |
| U7 | 失敗の理由が分からない | 結果に一言の助言を表示：強火で縮んだ → 「2個同時に開きそうなら弱火」／5/5 だが遅い → 「何も開いていない間は強火」／弱火のみ → 「強火も使ってみよう」 |
| U8 | 予兆 | 開く直前に揺れと泡を出す（`prefers-reduced-motion` のときは揺れをやめ、色の変化だけにする） |

### 2.6 1 画面操作（390×844）の維持

**新しい行は追加しません。** 目標時間・結果・助言は、既存のメッセージ行（V2 で高さ 38〜48px）と「ふっくら回収」
バッジに入れます。結果表示の例は「★★★ 6.4秒・5/5」（バッジ）と「名人まであと1.4秒！」（メッセージ）です。
U4 の +4px を加えても、V2 の実測（390×664 でも余白あり、§3.3）から収まる見込みですが、試作で
360×800 / 390×664 とあわせて実測します。貝のタップ領域は大きさに関係なく V2 と同じ（58×54 の SVG 単位）とし、
小さい貝ほど押しにくくなる問題を避けます。

## 8. シミュレーションの方法と限界

- モデル: `steamGameV2.ts` と同じ式（進み具合 `progress += 速さ × dt`、開いた後は縮み具合
  `exposure += 縮む速さ × dt`、`exposure ≥ 耐性` で縮む）を 10ms 刻みで計算しました。
- プレイヤーモデル（反応時間とタップ 1 回に必要な時間、反応時間は対数正規分布でばらつかせる）:
  - 初心者: 反応 0.9 秒、タップ 0.45 秒、変動係数 0.35
  - 中級者: 反応 0.6 秒、タップ 0.30 秒、変動係数 0.30
  - 上級者: 反応 0.35 秒、タップ 0.20 秒、変動係数 0.25
  - 火力を切り替えるときの反応は、通常の反応の 0.6 倍としました。
  - 一度に処理するのは 1 個で、回収は猶予の残りが最も少ない貝を優先します。最後に「ふたを開ける」までの
    反応時間とタップ時間も所要時間に含めます。
- 限界:
  - 見落とし、押し間違い、大きさの読み違いはモデルに入っていません。実際の初心者はもっと失敗します。
  - 予兆は「読み切替」方式の判断にだけ使っています。
  - 数値は相対比較のためのものです。体感の難しさは iPhone HV で確かめる必要があります。
- シミュレータのスクリプトはセッション内で提出しました（ランタイムに影響しないよう repository には入れていません）。
