```js
(() => { const real = Storage.prototype.setItem; window.__failSave = true;
  Storage.prototype.setItem = function (k, v) { if (k === "teto-pizza-preview-save-v1" && window.__failSave) throw new DOMException("quota", "QuotaExceededError"); return real.call(this, k, v); }; })();
```

### 5.1 保存失敗の種類と確認手段（補足）

表示文言は `src/state/roundNoticeCopy.ts`。失敗は `blocked`（保護による拒否）と `failed`（書込の失敗）に分かれ、どちらも「保存せずに先へ進まない」ことが期待結果。

| 種類 | 画面の理由文（要旨） | 自動テスト | 実機での再現 |
|---|---|---|---|
| `failed: quota` | 保存領域がいっぱいで書き込めません | Chromium E2E（模擬）・Vitest | E-1〜E-3（模擬、Mac）／E-5（実容量、Mac・任意） |
| `failed: unavailable` | 保存先に書き込めません（プライベートブラウズなど） | Vitest のみ | **Mac なし可**：プライベートブラウズ等で書込不可なら発生しうる。再現条件は端末依存で、**未確認**として扱う |
| `failed: dropped` / `mismatch` | 書いたデータが残らない／食い違う | Vitest のみ | 実機で自然には再現しにくい。**実機では確認不能**と記録する |
| `failed: oversize` | ピザの記録が大きすぎて保存できません | Vitest のみ | 通常の遊びでは再現しない。**実機では確認不能**と記録する |
| `failed: occupied` | 前回の調理の記録が保存に残っています | Vitest・（保持 journal は E2E⑦） | E-6（Mac・任意）で保持 journal を作った場合 |
| `blocked: stale-save` | 別の画面で保存データが更新されました | Vitest（模擬） | **E-4（焼成時の拒否）／D-3（CUT 中の競合）**（Mac なし可） |
| `blocked: load-failed` ほか（`unknown-schema`／`quarantine-*`／`storage-error`） | 起動時に読めなかった等 | Vitest のみ | 実機で自然には再現しにくい。**確認不能**と記録する |
| 解決不能 journal（`unknown-version`／`unresolvable`／`corrupt`／`oversize`） | 「完了していない調理の記録があります」＋「復旧:」 | Chromium E2E⑦（1 種）・Vitest | E-6（Mac・任意） |

いずれの種類でも確認する共通の期待結果：①BAKE（または次の工程）のまま止まる ②「保存せずに続ける」の選択肢がない ③所持数・図鑑・Pitz が変化しない ④再試行／再読み込みで復旧できる場合のみ先へ進む。

**二重登録防止・複数タブ**：D-1（通知を確認せず強制終了を 3 回）、D-2（連打）、D-3（2 タブ）、E-4（古いタブの焼成が止まる）が該当する。実機でしか確認できないのは D-1 と D-3 の実際の競合。いずれも**未実施**。

**Lunch Rush**：G-1〜G-8。最初の 1 枚の返却（G-6）は既知の例外で不具合として扱わない。Lunch Rush の導線名は未確認のため、実施者が記録する。
