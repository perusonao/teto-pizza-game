## 2. 評価規則の見直し（追加条件 1）

設計案（§2.1）の「★★ = 5/5（時間超過）**または 4/5 かつ時間内**」では、遅い 5/5 と速い 4/5 が同じ★★になります。
試作では次のように変更し、**実装より先にテストで固定**しました（commit `6ee89262`、`steamGameV3.grade.test.ts`）。

| 評価 | 条件（あさり / ムール貝） |
|---|---|
| 名人 ★★★ | 5/5 かつ ≤ 5.0 秒 / ≤ 5.4 秒 |
| ★★★ | 5/5 かつ ≤ 7.0 秒 / ≤ 7.4 秒 |
| ★★ | 5/5（時間超過） |
| ★ | 2〜4/5（時間に関係なし） |
| × | 0〜1/5 |

テストで固定した性質:
- どの 5/5 も、どの 4/5 より上になる。
- 回収数が増えて評価が下がることはない。
- 回収数が同じなら、速いほうが下がることはない。
- 5 個未満では時間が評価に影響しない。
- 不正な入力は「×」になる。

あわせて、**弱火のみの理論最短（反応 0 秒）の 5/5 でも★★**であることを、2 種類 × 3 プリセット × 4 配置のすべてで固定しています
（あさりは最後の貝が 7.17 秒、ムール貝は 7.67 秒で開くため、それぞれ 7.0 秒 / 7.4 秒を超えます）。

## 5. 予兆が人の目で分かるか（追加条件 3）

- 動画（#12 拡大、#01 / #05b 等倍）では、予兆が出ている時間は弱火で約 0.67 秒（10fps で約 7 コマ）、強火で約 0.31 秒（25fps で約 8 コマ）です。
  貝が傾いてふたが少し開き、泡と淡い光が出ます。止めて見れば、どの貝の予兆かを判別できます。
- 自動プレイの読み切替（#05b）は、強火中の予兆を見て弱火に切り替え、その直後に貝が開いています。
  つまり予兆は、**判断のきっかけとして機能する長さ**はあります。
- ただし強火の 0.31 秒は短く、鍋の中の 40px ほどの貝の小さな変化です。**周辺視野で気付けるかどうかは自動検証では確かめられません。**
  iPhone 実機で Owner が確認してください（OD-V3P-3）。見えにくい場合の候補は次の 2 つです。
  - 予兆を長くする（`STEAM_V3_TELL` 0.08 → 0.12。強火で約 0.46 秒）
  - 予兆を目立たせる（泡を大きくする、湯気を出す）
