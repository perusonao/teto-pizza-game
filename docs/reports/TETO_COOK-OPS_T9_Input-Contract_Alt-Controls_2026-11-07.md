## 3. 共通入力契約（T6 と整合する共通項）

各操作は**自然なジェスチャを主**に保ち、代替は「同じ状態機械・同じ結果」へ別の入口を足す形にする。全操作のドラッグ統一・長押し統一はしない。

| # | 条項 | 内容 | T6 との対応 |
|---|---|---|---|
| C1 | 入力の正規化 | 状態機械は DOM／reducer／保存を知らない。入力は正規化した座標（箱の単位 0〜100）とイベント、時刻は引数で受ける | T6 §2・§5 と同じ |
| C2 | 同一結果 | ボタン／キーボード代替の結果の質はジェスチャと**同じ**（劣らない・優遇しない） | T6 §4 |
| C3 | 最小操作領域 | 44px 以上（既存 CSS は 44／48px を 41 箇所で使用）。px 下限を併用（箱が小さい 360 幅対策） | T6 §3.4 |
| C4 | 指の固定 | 最初の pointerId を固定し、2 本目は無視。`touch-action: none` は操作層のみ | T6 §3.2、既存 `PizzaStage` |
| C5 | 中断 | `pointercancel`、`lostpointercapture`、`blur`、`visibilitychange: hidden`、向き／サイズ変更で CANCEL。**破棄か保持かを操作ごとに明記**（SEAR＝破棄、封止進捗＝保持） | T6 §3.2・§6、既存 |
| C6 | 誤操作の除外 | 短すぎる入力は何も保持しない（SEAR 0.35 s、FRY 0.6 s、CUT は最小長）。**閾値は操作ごとに根拠を記録**し、共通値は決めない | 既存 Result |
| C7 | 失敗の型 | 「評価に反映（BAKE・PREP）」と「何も起きない（短すぎる）」を混ぜない。見た目だけの不足（封止）は採点・保存に流さない | T6 §7 |
| C8 | 低いステージ | 実機のステージは約 260〜290px になり得る（PREP の HV）。**行（タイトル／本体／ボタン）構成でボタンを常に枠内**、要素の寸法で判定（media query に頼らない） | Sear.css／CookingPrep.css の先例 |
| C9 | 背面の遮断 | 操作中（busy）は dock・「焼く！」行を `inert`。結果表示中も背面を触れない | PREP HV-FIX、SEAR |
| C10 | 読み上げ | `role="status"` `aria-live="polite"`。進捗は割合を 25％刻みで | T6 §4 |
| C11 | モーション | `prefers-reduced-motion` ではアニメーションを即時に | T6 §4 |
| C12 | 色以外の手掛かり | 色だけが手掛かりの操作（SEAR・FRY・PREP）は、文言／形／煙などの冗長な手掛かりを併用する案を検討（要 Owner 判断） | 本書の新規観点 |
| C13 | 実機優先 | 新規・変更の入力は iPhone 実機 HV（HV Policy）を統合の前提とする。エミュレーションは参考 | HV Policy |
| C14 | 本番化 | 本番 OFF のゲート、DEV／Preview 限定の入口、入口名が本番バンドルに残らない検査（既存の gate テストの型） | T6 §8–9 |

C1〜C14 は**契約書の項目**であり、既存コードに適用済みという意味ではない。既存の操作が C* を満たすかは §6 の表で「事実」と「未確認」を分けて示す。

## 4. 代替操作案（設計のみ）— 生地

自然なジェスチャ（ドラッグで輪郭を伸ばす）は維持。**押す／引くの段階操作を並置**する。

| 案 | 内容 | 長所 | 短所・要確認 |
|---|---|---|---|
| D-A **ステップボタン** | 「ひろげる（＋）」「ちぢめる（−）」を生地の下に置き、1 回で全周を数％ずつ等方に。方向ごとの変形は無し | 実装が単純。「完成」の判定（面積到達）に合う | 手で伸ばす楽しさが無い。楕円・不整形（8 点）の表現は不可 |
| D-B **方向パッド** | 8 方向（上下左右＋斜め）を選んで＋／−（8 点の各点に対応） | 8 点輪郭を保てる | 操作が増え、1 画面（低いステージ）に収まりにくい |
| D-C **ハンドル選択** | 輪郭上の 8 点をタップで選び（フォーカス）、＋／−（またはキーボード矢印）で動かす | キーボード・VoiceOver に向く | 画面のタップ領域（44px）と 8 点が近接し、誤選択しやすい |

推奨（設計案）: **D-A を基本、D-C を上級／アクセシビリティ用**として段階導入。【推論】
確認事項: 8 点 `DoughShape` の更新イベントと `COMMIT_DOUGH_STRETCH` の関係、Reference 描画・採点（面積、円からのずれ）への影響。**実装は HOLD。採点への影響は別設計**。
