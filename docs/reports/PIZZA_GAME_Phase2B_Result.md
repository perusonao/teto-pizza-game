## 3. 実装内容

### 3.1 オリーブオイル（P1-1）

`PizzaStage.tsx` で塗布ソースが `olive-oil` の場合のみ `pizza-sauce-layer--oil` クラスを
付与し、単色 `backgroundColor` インライン塗りをやめた。CSS側は以下の3層で構成：

1. 左上・右下2箇所の半透明白ハイライト（`radial-gradient`）＝「艶」の視覚的合図
2. 全体を覆う淡いオリーブ〜黄土色の放射グラデーション（トマトソースより大幅に低い
   不透明度。生地色を完全に覆わず透けさせる）
3. `inset box-shadow` によるうっすらとした縁の陰影

一度、オリーブの色味を強めに作った結果、後述のクアトロ フォルマッジのチーズが
背景と同化して見えなくなる問題が発生したため（4章参照）、不透明度を大きく下げて
再調整した。

### 3.2 4種チーズの識別（P1-2）

`Ingredient.emoji` は変更せず（データ構造の破壊的変更を避けるため）、`category === "cheese"`
の場合だけ絵文字の代わりに `pizza-cheese pizza-cheese--{id}` クラスを持つ空の `<span>` を
描画するようにした。同じコンポーネントをトレイのアイコン（`IngredientTray.tsx`）とピザ上の
配置済みトッピング（`PizzaStage.tsx`）の両方で再利用しているため、プレイヤーがトレイで
見た形とピザ上の見た目が一致し、学習しやすい。

| チーズ | 形状 | サイズ | 色/質感 |
|---|---|---|---|
| モッツァレラ | 丸みのあるいびつなブロブ | 28×23px（4種中最大） | 白〜クリーム色、内側ハイライトで柔らかい光沢 |
| ゴルゴンゾーラ | 小さくいびつな塊 | 19×17px | クリーム色ベース＋青灰色の斑点4つ（カビ模様） |
| パルミジャーノ | 薄い角ばった削り片、-18°回転 | 21×9px（4種中最小・最も細い） | 淡い黄金色のグラデーション |
| フォンティーナ | きれいな円形 | 22×20px | オレンジ〜琥珀色、内側ハイライトで溶けたような光沢 |

いずれにも共通で「白い縁取り（box-shadow）＋落ち影」を追加し、背景（生地やオリーブオイル層）
の色に関わらずピザ上で埋没しないようにした（4章で発見・修正）。

### 3.3 焼成ビジュアル（P1-3、最重要項目）

Phase 2AからClassifyBake（raw/perfect/burnt）自体は存在したが、見た目への反映が
「フィルタ（saturate/brightness）」と「単一の放射オーバーレイ」に留まっており弱かった。

- `.pizza-dough--raw/--perfect/--burnt` の**背景グラデーション自体**をそれぞれ
  白っぽい生地色／黄金色／黒褐色に変更（filterだけでなくbackground-imageを差し替え）
- burnt時のみ `.pizza-char-spots` （複数の放射グラデーションを重ねた斑点パターン）を
  ピザ全面に追加し、「焦げ斑点」を表現
- `.pizza-dough--raw .pizza-topping` / `.pizza-dough--burnt .pizza-topping` という
  子孫セレクタで、生地の焼き加減に応じて**トッピング（チーズ・バジル・にんにく等すべて）
  にも**フィルタをかけ、raw時はわずかに淡く、burnt時は明度・彩度を落として焦げ色に
  変化させた（個別のJSXロジックを増やさず、CSS側だけで「具材にも焦げ感」を実現）
- チーズについては `bakeState` に応じて `pizza-cheese--melted`（perfect/burnt時に
  拡大＋光沢アップ）／`pizza-cheese--charred`（burnt時にさらに暗色化）を付与し、
  「チーズが溶ける」感を追加
- 既存の `.pizza-bake-overlay--burnt` の不透明度は、上記の変更で情報量が増えたため
  黒つぶれしすぎないよう調整（rgba値を弱める）

Blueのコメント選択ロジック（`App.tsx` の `resultLineKey`）・スコアの★上限補正
（`scoring.ts`）・バッジ表示（`ResultPanel.tsx`）は**一切変更していない**。6章の
実機確認で、この既存連動が壊れていないことを確認した。

### 3.4 注文/図鑑モチベーション（P1-4）

`src/data/orders.ts` の `getNextOrder()` に `dex`（発見済みレシピID配列）オプションを追加：

```
1. preferFirst → マルゲリータ（初回のみ、変更なし）
2. 未発見レシピが1件以上ある → その中から抽選（直前と同じレシピは、
   他に選べる未発見レシピがあれば除外）
3. 全レシピ発見済み → 全レシピから抽選（直前と同じレシピは、
   他に選べる候補があれば除外）
```

`gameReducer.ts` の `nextOrderState()` は既存の `dex` 引数をそのまま `getNextOrder()` に
渡すよう1行変更するだけで済んだ（`PLAY_AGAIN` / 初期化の呼び出し側は無変更）。
完全固定順にはしていない（未発見が複数ある間はランダム抽選）ため、「次は何かな」という
楽しさは維持される。

## 4. 実装中に発見して修正した問題（before/after）

最初のブラウザ確認で、意図と異なる見た目になっていた箇所を2つ発見し、実装内に
含めて修正した（このセクション自体が「厳しく自己評価する」ことの記録）。

**問題A: オリーブオイルの色を強めに作ったところ、クアトロ フォルマッジの
チーズ（特にフォンティーナ）が背景に溶け込んでほぼ見えなくなった。**
P1-1単体では改善に見えても、P1-2の「ピザ上でチーズが識別できる」を破壊していた。
オリーブオイル層の不透明度を大幅に下げ（黄土色グラデーションを0.34/0.40/0.46 →
0.16/0.20/0.24に）、全チーズに白い縁取り（box-shadow）を追加することで解決した。

**問題B: 検証スクリプトでチーズ配置直後にスクリーンショットを撮ったところ、
最後に置いたチーズがdrop-inアニメーション開始直後の縮小状態（scale 0.3前後）で
写り込み、実際には正しく描画されているチーズが「見えない」ように見えた。**
これはアプリ側のバグではなく検証スクリプト側のタイミング問題（アニメーション
完了前にスクリーンショットしていた）と判明したため、検証スクリプトに待機を
追加して撮り直した。念のため記録しておく。

修正後のオリーブオイル before/after 比較：

| before（生地のみ） | after（オリーブオイル塗布後） |
|---|---|
| `screenshots/phase2b-20260913/02-prepare-empty-before-oil.png` | `screenshots/phase2b-20260913/03-oliveoil-applied-after.png` |

2枚を見比べると、after側は2箇所の光沢ハイライトと全体的な黄土色の色味が付き、
生地のみの状態と明確に区別できる。

## 8. raw / perfect / burnt 比較（第三者判別レビュー）

| 状態 | スクリーンショット | 見た目の特徴 |
|---|---|---|
| perfect（マルゲリータ） | `05-bake-perfect-margherita.png` | 生地の縁が明るい黄金色〜キャラメル色。トマトソース面も鮮やかな赤のまま。焦げ斑点なし |
| raw（マリナーラ） | `06-bake-raw-marinara.png` | 生地の縁が淡いクリーム色〜白っぽい色（perfectより明確に薄い）。具材（にんにく・オレガノ・バジル）の色も心持ち淡い |
| burnt（クアトロ フォルマッジ） | `07-bake-burnt-quattro.png` | 生地全体が黒褐色。複数の焦げ斑点が散り、4種チーズもすべて暗く色褪せて「焦げた」トーンになっている |

3枚を並べて確認したところ、生地の縁の色（golden／pale cream／near-black）と、
burnt時の焦げ斑点・具材の暗色化により、スコアやバッジのテキストを一切見なくても
「どれが焼きすぎで、どれが生焼けで、どれがちょうど良いか」を判別できた。

一点、自己評価として正直に書いておくと、raw状態はトマトソースが生地面積の大半を
覆うレシピ（マルゲリータ・マリナーラ）では、赤いソースの上からの見た目変化が
生地の縁の色ほど劇的ではない（P1-3が要求する「生地が白っぽい」は縁の部分で明確に
出るが、ソースで覆われた中央部分では相対的に効果が弱い）。今回はクラウン（縁）の
色変化・具材フィルタ・Blueの専用セリフ・バッジの4点セットで「RESULTを見る前でも
分かるレベル」を達成できたと判断したが、ソースなしレシピ（クアトロ フォルマッジの
ような白ベース）の方がraw/perfect/burntの差はより劇的に見える。9章に既知の課題
として記載する。

## 9. known issues

- **raw状態の視認性はレシピ依存**: トマトソースが生地の大部分を覆うレシピ（マルゲリータ・
  マリナーラ）では、raw時の「生地が白っぽい」変化は主に生地の縁（crust）の色変化で
  表現される。ソース面積が小さい／白ベースのレシピの方が全体的な色変化はより劇的。
  縁の色変化＋具材フィルタ＋Blueの専用セリフ＋バッジの組み合わせで判別可能なレベルは
  達成しているが、「一目で圧倒的に分かる」という意味ではさらに強調する余地がある
- **トッピングのタップ座標とCSS配置座標にごく僅かなスケール差がある（Phase 2A由来、
  今回変更していない既存挙動）**: `PizzaStage.tsx` の `handleClick` はタップ位置を
  `circleRef.getBoundingClientRect()`（=境界線を含むborder-box全体、390px viewportで
  約300px）に対する割合で計算しているのに対し、実際のトッピング配置（`left/top`の%指定）
  は絶対配置要素の仕様上、境界線を除いたpadding box（約280px）に対する割合で描画される。
  そのため、生地の最外周（半径48%）に極めて近い位置をタップすると、置いた位置が視覚的に
  縁の下に隠れることがありうる（約7%程度の誤差）。今回の検証でも最初に極端な半径で
  チーズを配置した際に、意図せず縁付近に埋もれて見えたことがあった（4章の教訓を反映し
  検証は生地の内側寄りに調整した）。実プレイでは生地の中心寄りにタップすることが多いため
  通常は問題になりにくいが、Phase 2B/3で座標系を統一する余地がある（ドラッグ全面刷新は
  今回スコープ外のため見送り）
- **図鑑（`DexOverlay.tsx`）の材料ピル表示は4種チーズとも同じ🧀絵文字のまま**: P1-2の
  対象は「トレイ＋ピザ上」での識別であり、図鑑の参照用リストは対象外としたため、あえて
  変更していない。一貫性を高めるなら、図鑑側にも同じCSSスウォッチを使う拡張余地がある
- 監査資料 `PIZZA_GAME_Phase2A_PostMerge_Fresh-Gameplay-Review.md` 及び
  `screenshots/phase2a-fresh/` は0章に記載の通りこのリモートセッションからは
