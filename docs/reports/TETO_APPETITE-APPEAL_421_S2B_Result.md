## 3. 確認結果
### 3.1 ソース・バジルとの重なり
- バジル（M1 と同じ描画順）は常にチーズの上に乗り、葉がチーズに隠れる例はありません。ソースはチーズの周囲にそのまま見え、チーズの縁との境も自然です（`cluster`）。
- チーズ同士が重なると、同じ色のため**1 つの大きな塊（雲状）**に見えます。M1 は楕円の縁取りで 3 個が見分けられますが、Canvas では個数が読み取りにくい。ピース融合は S3 の範囲なので手を入れていません。

### 3.2 サイズ
| | M1 | Canvas（既定 54px） |
|---|---|---|
| 焼く前（生の塊）の直径（面積換算） | 約 25 px（28×23） | 約 22 px（−14%、丸い小さな玉） |
| 焼き上がりの直径（同） | 約 29 px（×1.16） | 約 36 px（+20%、面積は +46%） |
- 焼成前は M1 より小さく丸いので、**置いたときの見た目が M1 と変わります**（`1-making` 画像）。`&cheesePx=62` で焼く前を M1 並みに合わせられますが、その場合は焼き上がりが約 41 px になります。**S2-C の前に、どちらに合わせるか Owner の判断が必要**です（サイズ係数だけの調整で済み、輪郭の再生成は不要）。
- 溶けは melt 0.5〜0.9（heat 0.5〜0.9）の間に生の塊から焼き上がりへ移るため、焼成 1.0s（まだ生の塊）→ 1.7s（ほぼ焼き上がり）で大きく変わります。M1 は線形に 1.16 倍までです。

### 3.3 輪郭切れ・縁寄り
- 縁寄りの配置（`edge`）でも輪郭は切れず、生・溶け・焼き上がり・RESULT の全段階で M1 と同様にピザ内に収まります。ピースの輪郭は 64／96 とも最小 3px の余白内に収まっています（キャンバス要素の端で切れた例はありません）。

### 3.4 SVG フィルタ（`PieceReliefFilter`）・CUT
- 既存の複製構造（CUT 後は各ピースが本体のコピーを持ち、`clip-path` で切る）のまま動作します。3 回カット後、チーズを含むピースごとにキャンバスが複製され（散らばり配置で 5 個）、**切れ目をまたぐチーズも切れ目で正しく分かれ、切り離しの距離も M1 と同じ**です。複製は同じシードなので、全ピースで同じ形です。
- `.pizza-pieces` の SVG フィルタ（微小な起伏）を通ってもチーズの輪郭に破綻はありません。DPR 3 の実画素でもエッジに目立つ乱れは見えません。
- 複製ごとの描画は共有ビットマップの `drawImage` のみで、再描画はプロパティ（melt・toast・char）が変わった時だけです（カット操作中の再レンダーでは再描画しません）。

### 3.5 見た目の既知の問題（Owner の判断材料）
1. **色**: Canvas のチーズは M1 より**くすんだ乳白色**（芯 (238,234,218) の艶消し）で、M1 の白いハイライトと縁取りがありません。小さい表示では粘土・雲のように見えます。実物写真の数値には合うが、ゲームの他の素材（バジルの明るさ）と並ぶと沈みます。
2. 焼き斑・焼き色は、この表示サイズ（約 36px）ではほとんど見分けられません。
3. toast / char は 8 段階の量子化です。焼成中の滑らかさは動画で未確認（静止画のみ。Human Verification 動画は、既定表示が M1 のままで本番に出る変更が無いため作成していません。必要なら 390×844 の短い動画を別途撮ります）。
4. 密集配置で塊に見える（上記 3.1）。
5. 焼成前の生の塊が M1 より小さい（上記 3.2）。

## 4. 性能
計測条件: Chromium（このコンテナのソフトウェア描画）、390×844、DEV サーバ（未最小化）、実時間のマルゲリータ 1 周（散らばり、モッツァレラ 3 個）。**焼成 = 「焼く」から針が 66 に達する約 2 秒**、**CUT〜RESULT = 3 本のカットから RESULT 表示まで**。各モード 10 回の中央値（RESULT 静止のみ 5 回）。1×＝等倍、4×＝CPU 4 倍スロットル（スマホの目安）。M1 比は CDP の `TaskDuration`（メインスレッドの総処理時間）の差。

### 4.1 フレームとメインスレッド（M1 比）
| 区間 | 指標 | M1 | Canvas 64 | Canvas 96 |
|---|---|---|---|---|
| 焼成 1× | メインスレッド処理 | 718 ms | 688 ms（**−4%**） | 755 ms（**+5%**） |
| 焼成 1× | フレーム平均 / p95 / 最大 | 16.7 / 16.8 / 16.8 ms | 16.7 / 16.7 / 16.8 | 16.7 / 16.8 / 16.8 |
| 焼成 1× | 25ms 超のフレーム（1 回あたり） | 0.6 | 0.2 | 0.3 |
| 焼成 4× | メインスレッド処理 | 2317 ms | 2311 ms（**−0.3%**） | 2311 ms（**−0.3%**） |
| 焼成 4× | フレーム平均 / p95 / 最大 | 26.4 / 50.1 / 125 ms | 25.0 / 50.0 / 100 | 26.3 / 58.3 / 108 |
| 焼成 4× | 25ms 超のフレーム | 36.8 | 33.1 | 33.4 |
| CUT〜RESULT 1× | メインスレッド処理 | 377 ms | 492 ms（**+30%**） | 488 ms（**+29%**） |
| CUT〜RESULT 4× | メインスレッド処理 | 1704 ms | 1885 ms（+11%） | 1818 ms（+7%） |
| RESULT 静止 2 秒 1× / 4× | メインスレッド処理 | 102 / 445 ms | 110 / 462（+7% / +4%） | 113 / 465（+10% / +5%） |

- **焼成中は M1 比 +10% 以内**（−4%〜+5%、4× は ±0.3%）。スクリプト時間は +8〜20% 増えるが、チーズに掛かっていた毎フレームの CSS `filter` が無くなる分でスタイル再計算が約半分（35 → 18 ms）になり、相殺されます。フレーム時間は M1 と同等で、25ms 超のフレームも増えていません。
- **CUT〜RESULT は 1× で +30%（+約 115 ms、1 周の約 1.3 秒のうち）**。スクリプト時間は同等（91〜100 ms）で、差はスクリプト外の描画側です。原因は未特定（候補: SVG フィルタを通るキャンバスの再ラスタライズ）。4× では +7〜11%、RESULT 静止は +4〜10%。最大フレームは M1 と同程度（M1 133 → Canvas 133〜158 ms、4× 200 → 233〜242 ms で M1 の外れ値と同程度）。**暫定基準（+10%）はこの区間のみ 1× で超えています**。ただし区間の中身は操作（カットのドラッグ）が大半で、体感に直結するフレーム落ちの増加は確認できていません。
- 実機（iPhone / WebKit）では未測定です。

## 5. 64×64 と 96×96 の画質差（推奨解像度）
- DPR 3 の実画素（`*-dpr3-resolution.png`）でも、輪郭・陰影・色の差は小さく、96 は縁が僅かにくっきり、64 は僅かに柔らかい程度です。DPR 1（`*-compare.png`）では識別できません。
- 描画 −55〜60%、メモリ 16 KB 対 36 KB、前計算も僅かに軽い。S2-A の画像比較（RMSE 中央値 1.7）とも一致します。
- **推奨: 64×64 を既定**（現状の約 36px 表示では差が出ない）。**96×96 は、将来チーズを今より大きく（約 60px 以上）表示する場合のみ**使う（`CHEESE_POOL_GRID_CANDIDATE` は 64 のまま。`renderCheesePool` の既定は 96 のまま）。

## 6. S2-C への Go / No-Go
**判断: 条件付き Go。** 描画方式としては成立しています（焼成中の性能は M1 並み、CUT・SVG フィルタ・縁寄り・ソース/バジルとの重なりに破綻なし、64 で十分な画質）。S2-C の前に Owner が決めること / 片付けることは次の 4 点です。
1. **サイズの合わせ方**: 焼く前（M1 並みの 62px）か、焼き上がり（M1 並みの約 45px）か、現状の中間（54px）か。
2. **色**: くすんで見える点（3.5-1）。輪郭生成は再調整せず、明度・ハイライトの調整で良いか。
3. **CUT〜RESULT の +30%（1×）**: 原因の切り分け（キャンバス自体か、SVG フィルタとの組み合わせか）。
4. **WebKit**: このコンテナには WebKit が無く、**未検証**です（PR を作らないため CI でも走りません）。Safari での確認が必要です。

S2-C には進みません。
