## 1. 結論（要約）

| 観点 | 評価 |
|---|---|
| 表示（390×844 / 360×800 / 390×664） | スクロールなし、見切れなし、ボタンと貝のタップ領域はすべて画面内 |
| タップ精度 | 貝のタップ領域は 70×65（390×844）〜 59×55（390×664）px で、44px以上を確保。貝の間を押しても誤回収は起きない |
| 「待つだけ」対策 | 有効。強火のまま放置すると 0/5 |
| **難易度** | **弱火にしておくだけで簡単に5/5を取れる。** 弱火の回収猶予は 2.9〜5.2 秒あり、速く終えても何も得をしないため、弱火が常に最善になる |
| 単調さ | 開く順番は毎回 1→2→3→4→5 で固定（左上から右下）。乱数がないので、2回目以降は覚えて済む |

V1の「簡単すぎる」に対して、**強火のときだけ**は難易度が上がりました（回収猶予 0.84〜1.5 秒）。ただし弱火で安全に5/5が取れるため、火加減を判断する必要がまだありません。

### 2.1 回収猶予の計算値（`steamGameV2.ts` の定数から算出）

開く時刻 = `opensAt / 進行速度`、回収猶予 = `tolerance / 縮む速度`（火力を変えない場合）。

| 種類・火力 | 開く時刻（秒） | 回収猶予（秒） | 最後の貝が縮む時刻 | 同時に開いている最大数 |
|---|---|---|---:|---:|
| あさり・弱火 | 2.33 / 3.33 / 4.42 / 5.58 / 6.83 | 3.10 / 3.72 / 4.14 / 4.69 / 5.10 | 11.9 秒 | 4 |
| あさり・強火 | 1.27 / 1.82 / 2.41 / 3.05 / 3.73 | 0.90 / 1.08 / 1.20 / 1.36 / 1.48 | 5.2 秒 | 2 |
| ムール貝・弱火 | 2.83 / 3.92 / 5.17 / 6.42 / 7.83 | 2.90 / 3.55 / 4.03 / 4.66 / 5.17 | 13.0 秒 | 3 |
| ムール貝・強火 | 1.55 / 2.14 / 2.82 / 3.50 / 4.27 | 0.84 / 1.03 / 1.17 / 1.35 / 1.50 | 5.8 秒 | 2 |

- 強火は弱火より約1.8倍速く進む一方、縮む速さは約3.4倍です。そのため回収猶予は約1/3.4になります。
- 結果の判定は回収数だけで決まり（`verdict` は `rescuedCount` のみ）、かかった時間（`elapsedMs`）は判定にも表示にも使われません。そのため**強火を使う理由がゲーム内にありません。**

### 2.2 あさりとムール貝の比較

- ムール貝は、強火での最短の回収猶予が 0.84 秒（あさりは 0.90 秒）、最後の貝が開くのが 4.27 秒（あさりは 3.73 秒）で、強火なら少し難しくなります。
- 弱火ではどちらも猶予が約3秒以上あり、体感の差はほとんどありません。
- どちらも開く順番が配置順（1→5）と同じなので、見た目の違いは貝の大きさと色だけです。

### 3.1 見つかった小さな問題（いずれも本タスクでは修正していません）

1. **縮んだ貝をタップしても何も起きない。** `Shell` の `active` が `over` のときに false になり、`onClick` が呼ばれません。そのため用意されている「その貝は蒸しすぎ！次の貝を見よう」は表示されません（`SteamGameLabV2.tsx` の `pick` 内のこの分岐は到達しないコードです）。
2. **一度表示された通知が、次の開始かリセットまで残る。** 1個回収すると「貝Nをふっくら取り出した！」が出たままになり、「橙色の貝をタップして取り出そう！」の案内に戻りません。
3. **タップした貝に四角い枠が出る（Chromiumで確認）。** タップした `<g>` にフォーカスが移り、`:focus-visible` の枠が付きます（スクリーンショットの貝2など）。iPhone Safariで出るかどうかは実機で確認が必要です。
4. **貝の種類ボタンの高さが40px**で、ほかのボタン（44px以上）より低くなっています。
5. 結果画面では、「縮んでしまった（over）」と「取り出し損ねた（missed）」がどちらも灰色系で見分けにくいです。
6. 待機中は弱火/強火ボタンが無効で、開始すると必ず弱火になります（最初から強火を選べません）。

## 4. ゲーム性の評価（5個回収の操作）

- **タップしやすさ:** 良好です。貝のタップ領域は画面幅360でも 64×60px あり、間をタップしても誤回収しません。準備中の貝は光と黄色の点で目立ちます。
- **単調さ:** 単調になりやすいです。理由は次の3つです。
  1. 開く順番が配置順と同じで、毎回同じ（決定的で乱数なし）。指を左上から右下へ順に動かすだけになる。
  2. 弱火の場合、同時に開いている貝は最大3〜4個ですが、猶予が3秒以上あるので焦る場面がない。
  3. 弱火か強火かの選択に、時間・得点・見た目のどれでも差がない。
- **火加減の判断:** 現状では「最初から最後まで弱火」が最善で、切り替える意味がありません（シナリオ4の切替プレイも、弱火のみのプレイと結果は同じ5/5）。

## 5. 改善候補（Owner判断用・未実装）

優先順に並べています。どれも難易度・仕様の変更になるため、Ownerの承認が必要です。

1. **弱火に「代償」を付ける（最優先）:** 例えば、制限時間（「お客さんが待っている」）、時間に応じた評価（★）、または弱火で長く蒸すと全体の味が落ちる、など。これで初めて「強火で速く」と「弱火で安全に」の間に選択が生まれます。
2. **開く順番を配置順と変える:** 種類ごとに異なる順番にする、または大きさで開く時刻が決まるようにして、見た目（大きさ）から順番を推測する観察要素を入れる。
3. **弱火の回収猶予を短くする**（例: 縮む速さ 0.29 → 0.5/秒程度）。弱火でも油断できなくなります。
4. 上の小さな問題1・2（縮んだ貝のタップ時の反応、通知の残り続け）を直し、失敗したときに理由が分かるようにする。
