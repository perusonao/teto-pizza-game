## 3. V3 の仕組み（推奨）

### 3.1 火加減の数値化（作業 3）

| | 弱火 | 強火 | 比 |
|---|---:|---:|---:|
| 進行速度（V2 と同じ） | 0.12 /秒 | 0.22 /秒 | 強火が 1.83 倍速く開く |
| 縮む速度（V2: 0.29 / 1.0） | **0.32 /秒** | **1.2 /秒** | 強火は猶予が 1/3.75 |
| 回収猶予（V3 表） | 2.66〜4.38 秒 | 0.71〜1.17 秒 | |
| 最も短い猶予（最悪ケース） | **2.66 秒**（小） | **0.71 秒**（小） | |
| 最後の貝が開く時刻（あさり / ムール貝） | 6.67 / 7.17 秒 | 3.64 / 3.91 秒 | 強火は約 3 秒早い |

- **強火のメリット:** 閉じている間（何も開いていない時間）は損がない。全部閉じている時間を強火にすると、最後の貝が約 3 秒早く開く → 案 A の基準時間に届く。
- **弱火のメリット:** 同じ大きさの 2〜3 個が同時に開いたとき、強火では 3 個目のタップが猶予（0.88 秒）に間に合わない（反応 r ＋ 指の移動 0.30 秒 × 2 ≤ 0.88 → r ≤ 0.28 秒が必要、人にはほぼ不可能）。弱火なら同じ 3 個の猶予が 3.28 秒あり、初心者でも全部取れる。
- **切り替える理由:** 「閉じている間は強火、同じ大きさの貝が揺れ始めたら弱火、取り終えたらまた強火」。これが ★3 への最短ルートで、モデルでは熟練の ★3 が 99〜100%（強火のみは 21〜67%、弱火のみは 0%）。

### 3.2 貝の表と「見た目で順番が読める」仕組み（作業 4）

ルールは1つだけ: **小さい貝から開く。同じ大きさの貝は一緒に開く。** 貝の大きさの段差は 12% 以上（V2 は「ふつう 1.00 と 1.04」が見分けられなかった）。

| 種類 | 貝（大きさ × 個数） | 開く進行値 | 許容（縮むまでの量） | 構成のねらい |
|---|---|---|---|---|
| あさり・大小まざり | 小 0.80 ×1 / 中 1.04 ×3 / 大 1.28 ×1 | 0.26 / 0.50・0.51・0.52 / 0.80 | 0.85 / 1.05 / 1.40 | 中盤に **3 個同時**の山場。強火のままだと必ず取りこぼす |
| ムール貝・大粒 | 小 0.86 ×2 / 中 1.08 ×1 / 大 1.30 ×2 | 0.30・0.31 / 0.55 / 0.85・0.86 | 0.85 / 1.05 / 1.40 | 序盤と終盤に **2 個同時**。山場が2回で、切り替えも2回必要 |

- 同時に開く貝は進行値を 0.01 ずつずらす（完全同時だと見た目の順番が決まらず、テストの順序も曖昧になるため）。
- **配置（位置）は大きさと無関係**。各種類に**固定レイアウト 3 種**（5 か所の位置への割り当ての並べ替え）を用意し、1 回目＝レイアウト 0、「もう一度蒸す」ごとに 1→2→0 と回す。乱数は使わない。
  - どのレイアウトも「左上から右下へ読む順＝開く順」にはしない（V2 の暗記ルートを消す）。
  - テストはレイアウト番号を注入して固定する（URL パラメータは増やさない。コンポーネントの props / reducer の初期値で渡す）。
- **開く直前の合図:** 開く 0.06 進行手前（強火で約 0.27 秒、弱火で約 0.5 秒前）から貝がカタカタ揺れる。待機中（スタート前）から 5 個の大きさは見えているので、プレイヤーは「中が3つ並んでいる → 中盤で弱火」と**事前に計画できる**。
- reduced-motion: 揺れの代わりに貝の上に小さな泡の点を出す（動きなし）。

### 3.3 初心者・熟練者の成功率と操作猶予（作業 5）

モデル: 反応時間は対数正規（熟練 中央値 0.42 秒・σ0.20、初心者 0.85 秒・σ0.30、ゆっくり 1.10 秒・σ0.30）。タップは1本指で順番に、次のタップまで 0.30 秒（指の移動）。火加減の切替もタップ 1 回として数える。400 試行。「切替」は開いた貝があるときだけ弱火、「計画切替」は開いた＋揺れている貝が 2 個以上のときだけ弱火（§3.1 のルート）。

| V3 推奨（★3 基準 あさり 6.0 / ムール貝 6.8 秒） | 熟練 5/5・★3 | 初心者 5/5・★2以上・★3 | ゆっくり 5/5 |
|---|---|---|---|
| あさり・弱火のみ | 100%・★3 0% | 100%・100%・0% | 99.8% |
| あさり・強火のみ | 21.5%・21.5% | 0%・0.5%・0% | 0% |
| あさり・切替 | 79.7%・78.5% | 0.7%・5.5%・0% | 2% |
| あさり・**計画切替** | **99.3%・99.3%** | 20%・29.7%・3% | 1.8% |
| ムール貝・弱火のみ | 100%・0% | 100%・100%・0% | 99.5% |
| ムール貝・強火のみ | 67.2%・67.2% | 0%・8.3%・0% | 0% |
| ムール貝・切替 | 26.8%・26.8% | 0%・2.2%・0% | 0% |
| ムール貝・**計画切替** | **100%・100%** | 39.3%・41.5%・4% | 6.8% |

固定反応時間（テストで再現できるシナリオ。反応 0.4 / 0.6 / 0.9 秒、指の移動 0.30 秒）:

| シナリオ | V2 | V3 推奨 |
|---|---|---|
| あさり・弱火のみ | 5/5（7.9 / 8.3 / 8.9 秒） | 5/5（7.8 / 8.2 / 8.8 秒）→ ★2 |
| あさり・強火のみ | 5/5 / 5/5 / 4/5 | **4/5 / 4/5 / 1/5**（3 個同時で取りこぼす） |
| あさり・計画切替 | 5/5 / 5/5 / 4/5 | **5/5（5.29 秒）/ 5/5（5.71 秒）**/ 4/5 → 0.4・0.6 で ★3 |
| ムール貝・弱火のみ | 5/5（8.9〜9.9 秒） | 5/5（8.5 / 8.9 / 9.5 秒）→ ★2 |
| ムール貝・強火のみ | 5/5 / 5/5 / 4/5 | 5/5 / 4/5 / 2/5 |
| ムール貝・計画切替 | 5/5 / 5/5 / 4/5 | **5/5（5.98 秒）/ 5/5（6.40 秒）**/ 4/5 → 0.4・0.6 で ★3 |

読み取り:

- **初心者の安全な道:** 弱火のみで ★2 が 100%。最も短い猶予は 2.66 秒で、反応 1.1 秒でも間に合う。
- **熟練者の目標:** 「同じ大きさが揺れたら弱火」を覚えると ★3 がほぼ確実。反応 0.6 秒でも届く（瞬発力より判断）。
- **強火で連打する道は ★3 が不安定**（あさり 21.5%）→ 「速いだけ」では勝てない。
- 初心者が切替に挑むと 5/5 が 20〜39% に落ちる。これは意図した「上達の余地」だが、失敗時のメッセージで次の一手を教える（§5）。
- ★3 の基準時間（あさり 6.0・ムール貝 6.8 秒）は「計画切替・反応 0.6 秒」の終了時刻（5.71 / 6.40 秒）に約 0.3〜0.4 秒の余裕を足した値。弱火のみの最速（7.8 / 8.5 秒）より 1.7 秒以上短い。

### 3.4 ★3 の基準時間

| 種類 | ★3 基準 | 根拠 |
|---|---:|---|
| あさり | 6.0 秒 | 計画切替（反応 0.6）5.71 秒 +0.29 / 弱火のみ最速 7.77 秒 |
| ムール貝 | 6.8 秒 | 計画切替（反応 0.6）6.40 秒 +0.40 / 弱火のみ最速 8.49 秒 |

時間は「ふたをして蒸す」から「ふたを開ける」まで（V2 の `elapsedMs` と同じ定義）。蒸している間は時間を表示しない（カウントダウンなし）。結果画面にだけ「6.3 秒（★3 は 6.0 秒以内）」と出す。

## 4. 検証モデル（再現方法）

`steamGameV2.ts` と同じ式をそのまま使う: 進行 += dt × 進行速度[火]、進行が開く値に達した貝だけ dt × 縮む速度[火] を積算、積算 < 許容なら ready。プレイヤーは ready を見つけてから反応時間後にタップ（開いた順に処理、1 本指）。全部の貝が回収か縮むまで終わったら、反応時間後に「ふたを開ける」。dt = 2 ms、乱数の種 755。スクリプトは付録 A（実装の参考。テストに入れるかは実装 Gate で判断）。

制限: 視線移動・誤タップ・iPhone Safari のタップ遅延は入っていない。初心者の「計画」能力は過大評価の可能性がある（初心者に計画切替をさせているため）。実機 HV で確かめるべき点は §8。

## 付録 A: シミュレーション（参考実装、Python 3）

import math, random
P = {"low": 0.12, "high": 0.22}                     # 進行速度（V2 と同じ）
E_V3 = {"low": 0.32, "high": 1.2}                   # V3 推奨の縮む速度
V3 = {  # (大きさ, 開く進行値, 許容)

}
def run(shells, E, policy, react, gap=0.30, dt=0.002, cue=0.06, tmax=30.0):
    n=len(shells); prog=0.0; exp=[0.0]*n; resc=[False]*n; opened=[None]*n; planned={}; nf=0.0; plan=None
    heat = "low" if policy == "low" else "high"; t = 0.0
    while t < tmax:
        for i,(_,oa,_) in enumerate(shells):
            if prog >= oa-1e-9 and not resc[i]:
                opened[i] = t if opened[i] is None else opened[i]; exp[i] += dt*E[heat]
        prog = min(1.5, prog+dt*P[heat]); t += dt
        ready = [i for i in range(n) if opened[i] is not None and not resc[i] and exp[i] < shells[i][2]]
        for i in sorted(ready, key=lambda k: opened[k]):
            if i not in planned: at=max(t+react(), nf); planned[i]=at; nf=at+gap
        if policy in ("switch", "cluster"):
            soon = sum(1 for i in range(n) if opened[i] is None and prog >= shells[i][1]-cue)
            want = ("low" if len(ready)+soon >= 2 else "high") if policy == "cluster" else ("low" if ready else "high")
            if want != heat and plan is None: at=max(t+react()*0.8, nf); plan=(at,want); nf=at+gap
            if plan and t >= plan[0]: heat=plan[1]; plan=None
        for i,at in list(planned.items()):
            if t >= at and not resc[i]:
                resc[i] = exp[i] < shells[i][2]; planned[i] = math.inf
        if all(resc[i] or (opened[i] is not None and exp[i] >= shells[i][2]) for i in range(n)):
            return sum(resc), max(t, nf)+react()
    return sum(resc), tmax
def star(r, f, t3): return 3 if r==5 and f<=t3 else 2 if r==5 else 1 if r>=3 else 0
