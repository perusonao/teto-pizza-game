### 最低 5 枚に届かなかった理由（ブロッカー）
この実行環境のネットワークポリシー（エージェントプロキシ）が、画像ホストへの接続を拒否する（`CONNECT tunnel failed, 403`）。確認したホスト:
`commons.wikimedia.org`、`upload.wikimedia.org`、`en.wikipedia.org`、`unsplash.com`、`images.unsplash.com`、`www.pexels.com`、`images.pexels.com`、`pixabay.com`、`cdn.pixabay.com`、`flickr.com`、`live.staticflickr.com`、`www.seriouseats.com`。
Web 検索は動くが、ページを要約するだけで画像そのものは見えない。検索で見つかった `pixel-shot.com` は有料のストック写真で、利用条件が確認できず基準にしなかった。
**そのため、基準は上の 1 枚のみ。「最低 5 枚」の要件は未達。** 解除方法は 2 つ: (a) 環境の Network access で上記の画像ホスト（例: `commons.wikimedia.org`、`upload.wikimedia.org`）を許可する、(b) Owner が追加の写真（ブッラータ・シュレッド・極端に焦げたものを除く）を添付する。AI 生成画像は使っていない。

## Phase 2: 現行描画（`e324456`）の問題と原因
| 見た目の問題 | 原因のコード（`cheesePool.ts`） |
|---|---|
| 白いぼやけ・霧・発光 | 縁が `smoothstep(1+0.35w, 1-0.65w, rho)`（幅 0.05〜0.16）で広く柔らかく、外周の不透明度の床が 0.52 と低い。淡いクリームが半透明で赤いソースに載ると、ピンクがかった白いもやに見える |
| 紙のように硬い陰影 | 厚みを「中心の plateau から外周へ落ちる緩やかな傾斜」で作り、傾斜が半径の半分に及ぶ。法線の陰影が片側を広く暗くし、さらに乗算で灰色になる。実物は平らで陰影がごく弱い |
| 白い斑点 | 光沢の `pow(nh, 80) * smoothstep(noiseHigh) * 9` が、1 画素の硬い白いグリントを作る |
| 輪郭と内部の色が連動しない | 色の「厚み」（`thick`）、不透明度、縁のぼかし幅が別々の式で、縁が柔らかいのに lip は暗いなど、互いに矛盾する |
| クリーム〜黄色い全体色 | 本体全体を `GOLDBODY` / `CREAM` へ寄せていた。実物は乳白色が主体で、黄変しない |
| 複数ピースの接触 | 各ピースは別の canvas で、アルファ合成で重なるだけ。実物のように溶け合わない（**未解決**。下記） |

**構造上の原因（パラメータでは直らない）**: 旧描画は「不透明で盛り上がったドーム」を前提に、透け・ぼかし・色を後から重ねる設計だった。実物は「平らで薄い、明るい乳白色のシート＋明瞭な縁」で、前提が逆。

## Phase 3: 描画構造の変更（`renderWithGeometry` のみ）
- 旧描画を `renderLegacyPixels`（`dc1d20b` と同一のコード）として残し、新しい `renderMeltedPixels` を追加。melt に応じて `fx = smoothstep(0.3, 1, melt)` で両者を**連続的にクロスフェード**する。`fx = 0`（melt ≤ 0.3）では旧描画そのもの。輪郭（アウトライン）は共通で、旧版と同一。
- **形状**: 平たいシート＋全周に細い盛り上がり。縁は約 5 % の半径幅で明瞭。外周のごく狭い帯（半径の外側 10 %）だけが不均一に半透明。
- **表面**: 乳白色（`MILK`）が主体、クリームのまだらは小さく、ソースが透けた淡いピンクは縁と薄い数か所のみ（色の変化であり、アルファの霧ではない）。陰影は暖色で、範囲は狭い。
- **光沢**: なだらかなつやのみ。1 画素の硬いグリントは廃止。
- **焼き色**: 一部の縁の金色、縁寄りの小さな斑点、既存の blister のみ。本体全体の色づきは廃止。焼き過ぎは灰色ではなく深い金茶（`OVERBAKED`）。
- **安全対策**: `CheesePoolCanvas`（透明化検出・再描画・M1 フォールバック）は変更なし。

## テスト基準の変更と検出能力の監査
前回（`61b9a06` / `e324456`）は、旧デザイン用の基準を緩めて通していた。今回は**テストファイルを元（`dc1d20b`）に戻して**から、新描画で本当に落ちる基準だけを調べた。結果、最終的に元の基準を変えたのは**焼き色の割合（warm）の 2 か所のみ**。調整の途中で落ちた「中心色（青が約 3 ずれ）」と「サイズ・中心のずれ」は、テストではなく描画側（MILK の青、外周の拡大の廃止）で解消した。他（エッジ幅 < 7.5、半透明率 < 0.35、中心色 ~(238,234,218)±7、白飛び ≤ 7 %、アウトライン関連）は**元のまま通る**。

| 変更 | 旧 | 新 | 理由 |
|---|---|---|---|
| 満焼成の warm 中央値の下限 | > 0.15 | > 0.04 | 実物は焼き色がチーズ面積の数 %（blister のみ）。旧 15〜38 % は金色の縁と大きなパッチによるもので、実物より過剰 |
| 満焼成の warm 中央値・p95 の上限 | < 0.3 / < 0.4 | **< 0.14 / < 0.2（締めた）** | 新分布（中央値 0.07）に合わせる。黄変を検出できるようにするため |
| toast 0.6 の warm 中央値の下限 | > 0.08 | > 0.02 | 同上 |
| toast 0.6 の warm 中央値・p95・最大の上限 | < 0.18 / < 0.22 / < 0.26 | **< 0.1 / < 0.12 / < 0.16（締めた）** | 同上 |

追加テスト（4 件）: 焼成前のバイト一致（`dc1d20b` のハッシュ 7 件）、不透明な本体＋外周のみ半透明＋明瞭な縁、なだらかな表面（`shadeSpread` < 1.12）、焼き色は局所的＋焼き過ぎは灰色でなく茶色。

## 残る問題
1. **参照写真が 1 枚のみ**（要件は 5 枚以上）。ネットワーク制限による。基準が 1 枚では、写真ごとの個体差を考慮した共通特徴・例外の整理が十分でない。
2. **形状**: 突出する腕が残る（実物は丸い溜まり）。アウトライン生成（アーキタイプ）の変更が必要で、元のアウトライン用テスト（アスペクト・ solidity・曲率）と焼成前の互換性に影響するため、今回は変更していない。
3. **油の玉**・縁の淡いピンクの透けは未実装または弱い。
4. **複数ピースの接触**: 各ピースが別の canvas のため、実物のように溶け合わない。隣接すると重なるだけ。
5. iPhone 実機（Safari）と WebKit の画像は未確認。
