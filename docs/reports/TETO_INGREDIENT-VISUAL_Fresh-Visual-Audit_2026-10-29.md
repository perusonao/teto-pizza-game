## 0. 結論（先に）

1. **実装済みの食材は 92 種**（ソース 13・チーズ 13・具材 66）。ピザ上に置く 79 種（チーズ 13 + 具材 66）を全件、**実ゲーム画面**（Chromium、390×844 / 360×800、DPR 2）で撮影・測定した。**全 79 種を実画面で確認できた**。ソース 13 種は塗り表現のため別枠（§5.6）。
2. **描画方式で品質が割れている。** 専用 SVG 25 種（平均 3.0 / 5）、Canvas のモッツァレラ（3.8）、汎用 CSS 円のチーズ 10 種（2.7）、OS 絵文字 43 種（2.6）。ピース 79 種の約 54%（43 種）が OS 絵文字で、ここが品質の下限を決めている。
3. **最も大きな問題は 3 つ。**
   - **A. 絵文字が食材を表していない／単色図形**（ペパロニ🔴・サラミ🟤・ブラックオリーブ⚫・ハラペーニョ🟩・生ハム🍥・イワシ🎏・塩ダラ🐡・ツナ🐠・豚肉🐖 ほか）。Style Lock で**デザイン確定済み**の食材が多く、未実装なだけ。
   - **B. チーズの 10 種が「同じ白〜黄の円」**（§5.5、fig5）。完成ピザでチーズの種類を区別できない。
   - **C. 調理前後の変化がほぼ無い。** 具材の焼成による色差は中央値 ΔE 5.6（ほぼ気づけない）。エビは焼成後も淡いピンクのまま、牛肉は main では焼いても赤いまま（#697 の炒めはフラグ OFF）。新調理法（焼く・茹でる・あめ色炒め）の**前提を満たしていない**。
4. **重点 6 食材（牛肉・エビ・しらす・玉ねぎ・きのこ・チーズ）はどれも「致命的ではないが、課題が各 1 つずつ」**（§6.2）。最も深刻なのは**チーズ**（種類の区別）と**きのこ**（🍄 が赤いベニテングタケ型でポルチーニ SVG と別物）。

## 2. 調査方法と限界

- **環境**: dev サーバ（`TETO_TEST_HOOKS=1`、既存の e2e サポート `startTargetlessFreeCook` / `bakeToTarget` / `tapDoughPercent` を再利用）、Chromium（Linux、Noto Color Emoji）、**DPR 2**、390×844 と 360×800。ゲームコードは変更せず、撮影スクリプトは repo 外の scratchpad に置いた。
- **セーブ**: 全食材を所持・在庫 9 にした Free Cooking（`INGREDIENTS` 全件）。生地 → トマトソース → モッツァレラ 3 個 → 具材を、トレイの並び順 6 種ずつ（11 バッチ）× 各 2 個を固定の 12 スロットに配置 → 焼成（目標帯の中央）→ FINISH 画面 → RESULT 画面。チーズは別 3 バッチ（CHEESE 工程、トッピングなし）。
- **測定**: 各状態で「全食材を表示」と「ピース非表示（モッツァレラ Canvas の溶け面は残す）」の 2 枚を撮り、**差分から各ピースの擬似マスク**（閾値 → クロージング → 穴埋め）を作った。マスクから、見た目の大きさ（px、影の縁を含むため実体より約 2〜3px 大きい）・占有率・平均色（CIELAB）・背景（**ピースの真下の実際の背景**）との輝度比と ΔE76・輪郭（ピース縁の内側 vs 外側の ΔE）・色覚シミュレーション（Machado 2009、2 型色覚）・焼成前後の色差を計算した。
- **限界（必読）**
  1. **絵文字は Linux の Noto Color Emoji**。iPhone の Apple Color Emoji は形・色・大きさが異なる。**絵文字 43 種の「色・輪郭・サイズ」の数値は iOS では未確認**（意味の一致〔🎏が鯉のぼり等〕は OS 共通）。#623 も同じ注意を記録している。
  2. 配置は固定スロットで、実プレイの重なり・密度は再現していない。**食材どうしの重なり**は、ほとんどのピースで他の具材と重ならない配置（モッツァレラを除く最大の重なり率 0.49＝たまご）のため、**重なり時の判別は未確認**。
  3. チーズ 13 種の「背景との差」は**赤いソース上で単独に置いた**場合のみ測った。**チーズの上に別のチーズ・具材が載る場合は未測定**。
  4. 後乗せ（FINISH）層は `salmon-roe` / `shiso` / `white-sesame` / `nori` / `cilantro` / `pomegranate` のみ測った。
  5. 色コントラストの比（WCAG 式）は**参考値**。装飾画像に文字の合格基準（4.5:1 等）は適用していない。判断は輪郭 ΔE・形・意味を併用した。
  6. **評価点（5 段階）には、自動測定値とレビュー（意味の一致・形状の質）の判断が混在する**。自動部分の閾値は §5.3 に書いた。主観部分は「完成ピザ上の拡大図（fig2）」を見た判断。
  7. 実機 iPhone Safari・WebKit は未確認（本件は Chromium のみ）。

- **輪郭 ΔE（縁の内側と外側の差）が小さい（< 7）食材（赤・橙のソース／生地の上）:** ペパロニ 3.0・いくら 3.4（後乗せ層）・豚肉 3.8・チェリートマト 4.1・じゃがいも 4.3・ヴルステル 5.6・アーモンド 5.7・レモン 5.8・ベーコン 6.0・ピーマン 6.1・ズッキーニ 6.5・にんにく 6.5・ケッパー 6.8・パプリカパウダー 6.9。**赤い食材（ペパロニ・チェリートマト）と同系色の食材（じゃがいも・アーモンド）がソース／焼けた生地に埋もれやすい。**
- **輝度比が 1.15:1 未満（参考）:** アーティチョーク・アーモンド・生ハム・白ごま・ハム・イワシ・ヴルステル・アンチョビ・ホットドッグ・さつまいも・しらす・ベーコン。ただし輪郭と形で読めるものが多く、輝度比だけでは不合格にしていない。
- **2 型色覚での色差が小さい（ΔE < 8）:** パセリ・白ごま・ハム・ヴルステル・トマト・ホットドッグ・エビ・さつまいも・たまねぎ・ベーコン・わさび。色だけに頼らず形で読める食材は SVG 化済みのもの（ヴルステル・ホットドッグ・エビ）で、**絵文字のハム・ベーコン・さつまいも・たまねぎは色覚特性でも形が支え**。

### 5.4 焼成前後の変化

- **具材（チーズ以外）の焼成前 → ちょうど の色差 ΔE76 は中央値 5.6**（チーズを含む 79 種中、10 種が < 4、59 種が < 7）。原因はコードにある: `toppingVisualFrame`（`bakeVisual.ts`）の ちょうど（heat 1.0）の係数は **brightness 0.97・saturate 1.04・sepia 0.08** で、**全具材に同一**（緑のハーブのみ別カーブで、ちょうどは変化 0）。焼き過ぎ（heat 2.0）でも brightness 0.78・sepia 0.20。
- **fig3（焼成 生 → ちょうど → 焦げ）の所見（6 食材）:** 牛肉: 赤いまま（焦げで暗くなるが「焼けた」色ではない）。エビ: 淡いピンクのまま（焼成でも橙にならず、**生に見える**）。しらす: ほぼ変化なし。玉ねぎ: わずかに暗く（あめ色にはならない）。きのこ・ポルチーニ: わずかに暗く。焦げでは**生地とチーズが大きく暗くなり、具材だけが明るいまま浮く**。
- **チーズ:** モッツァレラは溶けて広がり ΔE 25。**汎用 CSS 円のチーズは拡大（×1.16）と色の微変化のみ**（スイスチーズ ΔE 25.7 は黄色寄りに変わるため）。fig5 参照。

### 5.5 チーズ 13 種（fig5）

- モッツァレラ（Canvas）、フェタ・リコッタ（SVG）は一目で別物。**残り 10 種は円**で、色が白 / 淡黄 / 橙（フォンティーナ）/ 青斑点（ゴルゴンゾーラ）と違うだけ。**クリームチーズ・カトゥピリ・ヤギのチーズ・パニールはほぼ同じ白い円**（22px、ΔE 差はごく小さい）。

- トレイのチップも同じ CSS 形状で、**色と大きさ（丸・小丸・棒）が違うだけ**（`tray-cheese` で確認。完成ピザと同じ見え方）。RESULT 等の文字列チップには全て 🧀 が付く。**トレイでも完成ピザでも、チーズの種類を形で選べない。**

### 5.6 ソース 13 種（fig7、390 のみ）

トマト・オリーブオイル・ジェノベーゼ・フロマージュブラン・豆板醤・カレーケチャップ・マスタード・柚子胡椒・味噌だれ・タヒニ・バーベキュー・醤油・クリームは、**色で区別できる**。ただし**濃い茶系（味噌だれ・タヒニ・BBQ・醤油・豆板醤）は互いに近く**、ジェノベーゼと柚子胡椒も緑系で近い。**暗いソースの上に暗い具材（牛肉の焼き色・ソーセージ・ブラックオリーブ）を載せた場合の見え方は未確認**（今回はトマトソース上のみ測定）。

## 12. 新調理法との依存関係

新調理法の設計資料は **main に存在しない**（`docs/design` に「茹で」の記述なし。別セッションの設計）。以下は**現行の描画から見た必要条件**であり、新調理法の仕様を決めるものではない。

| 新調理法 | 現行の描画で足りないもの | 必要な表現（将来） | 依存 |
|---|---|---|---|
| 牛肉の炒め（#697） | main の牛肉は赤いまま（フラグ OFF） | 実装中（生 → 炒め済み → 焦げ。SVG 色変数） | #697 |
| ソーセージ・ポルチーニの焼く | 焼成前後 ΔE 7.2 / 4.7。焼き目の表現なし | 焼き色（茶の濃淡）、断面の焼き目 | P2-1・P2-3 |
| エビの茹でる | 現行は**すでに茹で済み相当の淡いピンク**。生の状態が無い | 生（青白）→ 茹で済み（現行色）。尾・節は現行の形を維持 | P2-1・P2-2 |
| 玉ねぎのあめ色炒め | 🧅（絵文字）は色を変えられない | 専用 SVG（スライス）＋ 白→あめ色 | P2-4（Lock 外のデザイン） |
| きのこの炒め・焼き | 🍄 は別物（ベニテングタケ型）。ポルチーニ SVG は焼き変化なし | マッシュルームの新規 SVG、傘の焼き色 | P1-5・P2-5 |

**共通の前提:**
1. **現行の全具材フィルタ（`toppingVisualFrame`）は色相を変えられない**（brightness / saturate / sepia のみ）。状態表現は **SVG の色（CSS 変数）**で行うのが、#697 と同じ方式で、Style Lock の SVG 規約と両立する。
2. 保存・採点・在庫・Dex に出さない（#697 の `preparedLook` と同じ transient）。
3. **新調理法の「状態」が増えるほど、基準の SVG（生・茹で済みなど）を Style Lock 上でどの状態として固定するか**を先に決める必要がある（エビは現行 = 茹で済み、牛肉は現行 = 生）。
