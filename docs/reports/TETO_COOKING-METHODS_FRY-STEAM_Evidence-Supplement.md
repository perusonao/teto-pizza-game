### 2.3 判断材料としての整理
- **A と V3 は排他ではない。** V3 の Lab はゲーム本体に未接続なので、#738 を A で完成させても V3 の評価は妨げない。逆に、V3 を待って #738 を止める利点は、**作り直しの回避**だが、実際は #738 の SteamLayer（鍋・ふた・殻・蒸気の描画、ghost click 抑止、ステージ内の一時画面）が V3 本線化でも再利用される見込みが高く【推論】、作り直しの規模は小さい。
- **V3 を本線化する場合に必要な新設計**（実装は不可、設計課題の列挙のみ）: ①貝の結果 → `steamedLook` の amount 写像、②ステージ内に V3 の盤面（5 個＋予兆）が 390×844・390×664 で入るか（Lab は全画面）、③回収後の「個数」「★」をピース見た目へ反映するか（採点非影響の原則の確認）、④炒め・炙りと並べたときの 1 ラウンドの総所要時間。
- **結論**: 「A を暫定本線として #738 を終える」ことによるサンクコストは小さく、claim 失効・FRY の F3 待ちを解消できる。V3 は **Lab のまま実機 HV**（V2 の実機 HV は未実施のまま V3 が出ている点に注意）→ 結果が良ければ**別 Gate で接続設計**。

## 4. FRY F2 のゲーム性・評価・報酬設計（STEP 4）

### 4.1 前提（変更しない制約）
- Owner 判断（#749）: 採点・保存・在庫・Dex・Pitz・識別には**一切影響させない**。失敗状態なし。ゲージ・数値・残り時間なし。Production ON 禁止。
- F1 の実装（main）: 泡の段階 5 つ（big／medium／fine／calm／still）、見た目 3 つ（raw／crisp／over）、`amount` は時間で単調増加し over だけ厳密に 1、`fryLookOfAmount` で逆引き（全域でラウンドトリップをテスト）。時間境界 3.5 秒 crisp／8.5 秒 over は PROVISIONAL。
- S2 の雛形（reducer）: `state.steamedLook?.[id] !== undefined` なら状態不変（最初の確定のみ有効）、`amount` は reducer では clamp のみで意味は純ロジック側に置く【実測: `gameReducer.ts:1235-1245`】。F2 は同形で `fryLook` を足す想定。
- 「ゲーム性がない」（#755）の教訓: **結果が時間だけで決まり、判断・上達・やり直しがない**と評価が落ちる。

### 4.2 案
**案 α: 見た目のみ（現行 F1 のまま）**
- 報酬: 色・つや・泡が止まる瞬間・擬音（「ジュワワワッ！」→「ぷつぷつ」→「シーン…」）。引き上げ後に「まだ生っぽい／カリッと揚がった／揚げすぎ」の見た目の名前。
- 判断: 泡を見て引き上げ時刻を選ぶ（A: 2 タップ／B: 縦ドラッグ）。やり直しなし。
- reducer: `fryLook[id] = amount`（S2 と同形）。
- 利点: 最小。F1 の設計どおりで追加設計ゼロ。
- 欠点: 「見た目が変わるだけ」で、**再挑戦の動機がない**。Owner が蒸す A に下した評価と同種になる恐れ【推論】。

**案 β: 判断の可視化＋やり直し（非採点）［推奨］**
- 報酬（**採点・保存に出ない画面内のフィードバックのみ**）: ①引き上げ直後の「カリッ！」演出（黄金のつや、泡が静まる、短い音の擬音）、②ミトの一言（早い→「もう少し泡が細かくなってから」、ちょうど→「いい音！」、遅い→「ちょっと濃くなったね」）。**泡の変化＝手掛かりの言語化**で、「観察して上達する」軸を作る（V3 の U5・一言アドバイスと同じ発想）。
- 判断: A/B 共通で、泡の大きさ・勢いから引き上げ時刻を選ぶ。**確定する前に「やり直す」（具は皿に戻る、在庫消費なし）**を許す。確定後は S2 と同じく最初の 1 回のみ有効。
- 結果の読み出し: **保存するのは `amount` のみ**。見た目の名前・一言・演出は `fryLookOfAmount(amount)` から**導出**する（追加の状態・保存・採点なし）。
- reducer: α と同一（`fryLook[id] = amount`）。
- 利点: reducer 変更なしで「判断の理由」と「やり直し」が入る。本件の Owner 制約（採点・Dex・Pitz 非影響）に抵触しない。
- 欠点: 報酬が「演出」止まりで、**長期の達成感（ミニ記録・星）は無い**。やり直しが無限だと緊張感が薄れる（回数制限・やり直しの 1 回目だけ無料などは HV で調整）。

**案 γ: V3 型（複数枚・油温切替・時間評価）**
- 内容: 厚みの違う 3 枚のナス（見た目で厚さが分かる）を同時に揚げ、油温（低／高）を切り替え、薄い方が先に揚がる→揚げすぎる前に引き上げる。評価は結果画面でだけ時間・個数を示す。
- 報酬: V3 の★評価（5/5 かつ基準時間以内など）に相当。
- reducer: **1 食材 1 数値の `fryLook[id]`** に写すには、3 枚の結果を集約（平均・最小・最悪）する必要があり、情報が落ちる【推論】。
- 利点: 判断・上達・切替の理由が最も強い。蒸す V3 と「同じ遊び方」で揃う。
- 欠点: **F1 の純ロジック（単一の submerge 時間）を作り直す**必要があり、F1 の成果（79 tests）を一部捨てる。V3 自体が実機 HV 未実施なので、**まだ本線に移す根拠がない**。iPhone 1 画面に 3 枚＋油温＋やり直しを収める設計も要る。ナスの絵（G2）が前提で、HV は絵待ち。

### 4.3 比較
| 観点 | α 見た目のみ | β 判断の可視化＋やり直し | γ V3 型 |
|---|---|---|---|
| 判断性（観察→選択） | 低〜中 | **中〜高** | 高 |
| 上達・再挑戦の動機 | 低 | 中（やり直し＋一言） | 高 |
| 所要時間（1 回） | 6〜10 秒【見込み】 | 8〜14 秒（やり直し 1 回込み）【見込み】 | 15〜25 秒【見込み】 |
| iPhone 1 画面 | 余裕 | 余裕 | 要設計（3 枚＋油温） |
| reducer の形 | `fryLook[id]=amount` | **同じ** | 同じ（ただし集約で情報が落ちる） |
| F1 への影響 | なし | 小（`fryOffer`／UI の「やり直す」、純ロジックは追加） | **大**（単一 submerge の置換） |
| Owner 制約（非採点・非保存・失敗なし） | 適合 | 適合 | 適合（ただし★の置き場に注意） |
| HV の必要量 | A/B の手触り中心 | A/B＋泡の読みやすさ＋やり直し | 新規 Lab の HV から |
| 推奨度 | 最低限（フォールバック） | **推奨** | 別 Gate（Lab で先行検証） |
