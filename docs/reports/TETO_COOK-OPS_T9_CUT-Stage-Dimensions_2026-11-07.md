## 0. 方法

- 使ったレシピ: **マルゲリータ（ガイド付きの通常ラウンド）**。CUT 対象 recipe（`cookingProfiles.ts` の `CUT_ELIGIBLE_RECIPE_IDS`）の 1 つで、前回のフリークッキングは焼成後に CUT を経ずに RESULT へ進んだため、通常ラウンドに切り替えた。
- 到達手順（e2e の `reachCut` と同じ順をスクリプト化。**Playwright のマウス操作、dev ビルド**）: ホーム →「ピザを作る」→ マルゲリータ →「このピザを作る」→ 生地（縁を 8 回タップ）→ ソース（トマトソースを渦巻きでなぞる）→ チーズ（モッツァレラを 3 回タップ）→「焼く！」→ 約 2.05 秒で「取り出す！」→ CUT。到達判定: ボタンに「切り終わる →」が出ること。5 つの viewport すべてで **CUT に到達した**。
- 保存は新しいブラウザコンテキストに、マルゲリータ発見済みの最小の保存を注入（e2e の `startMargherita` と同形）。
- 測定: `getBoundingClientRect` の上端・高さ（px）。`.game-screen` の `clientHeight`／`scrollHeight`。
- 各 viewport で 3 時点: CUT 開始（線 0 本）、線 1 本、線 3 本（スワイプ操作）。

### 1.2 ステージの外の空き

- ステージ下端（Y+高さ）は、すべての viewport で**進捗表示（24px）の上端に接している**（空き 0）。進捗表示の下端はアクション行の上端に接する（例: 390×664 では 562+24＝586 と 594 の間に 8px）。**生地工程のような 212〜224px の空き帯は CUT 工程には無い**。

## 2. 読み取れること【推論】

1. **CUT 工程には固定の空き帯がない**（ステージが残りを使い切る）。前回の生地工程（トレイなし・空き 212〜224px）とは構造が違う。ボタン行を足すと、**ステージが縮むか、固定領域が増える**。
2. **ステージ自体に生地外の余白がある**: 低い画面（390×664）でも片側 約 28px、360×640 で約 30px。**生地の円の外側＝正方形ステージの四隅**には、さらにまとまった空きがある（円と正方形の差。SEAR のピルが低ステージで「角」へ移る先例と同じ領域）。
3. 低い高さ（664／640）では、注文カード（ガイド付きラウンドのみ、44px）と工程タブ（44px）が上を占め、ステージは 391〜418px。**フリークッキングでは CUT 工程自体が無い**（前回確認）。したがって C-A′ の入口はガイド付きラウンド（と CUT 対象 recipe）の画面だけの問題。
4. 縦スクロールは全 viewport でなし。**#766（RESULT のヒント行）の再現条件とは別の画面**で、CUT 工程そのものは 1 画面に収まっている【参考値。#766 の再現そのものは今回の対象外】。

## 3. 折りたたみ表示（C-A′）への示唆

| 案 | CUT 工程での収まり |
|---|---|
| 生地の下に 44px の見出し行 | ステージを 44px 削るか、進捗表示の行に並べる必要がある。低い画面（390×664）でステージが 415→371px（生地 359px に対して 12px の余裕）になり、**生地を縮める**かもしれない（`PizzaStage` の寸法計算次第。未確認） |
| **ステージの角（円の外）に小さなトグル**（SEAR のピルの先例、56×52） | ステージの寸法を変えず、生地に重ならない。**角の空きは 390×664 の円（359px）と正方形（390×415）の差から、片隅に 56×52 を置く余地があると見積もれる**【推論。実描画での重なりは未確認】 |
| 進捗表示（24px）の行に「点で切る」トグルを並べる | 24px では 44px のタップ領域を満たさない。行の高さを増やせば固定領域が増える |

**推奨（暫定）**: CUT 工程は、生地工程と違い、**角のトグル（O3 風）を基本**にする案が有力。開いたときの「切る」「やめる」のシートは、ステージ内の余白（生地の上下）に収める。Owner の初期案（見出し「別の操作方法を使う」・折りたたみ）の文言は保つ。**実機での重なり・タップ領域は未検証。**
