# parmigiano の「タップごとの局所散布」— 散布のまとまりを改善する選択肢（docs-only、PR #875）

状態: **docs-only の比較資料（コード変更なし）。** Owner の承認: [#875 comment 7007821371](https://github.com/perusonao/teto-pizza-game/pull/875#issuecomment-7007821371)（HV の所見）とその後のチャット指示（docs-only 案の作成）。実装・merge・Draft 解除・Production ON・共有 Preview 更新は未承認。HEAD `0318d2b9`（描画コードは rev.5 `950ec38b`）。

## 0. 何が問題か（HV の所見）
rev.5 の Preview（`950ec38`）で、Owner は「左・中央下・右上などの局所的な散布のまとまりが残り、広く自然に振りかけた一体感は限定的」と判定。幅広の一部がやや厚い欠片に見える点は別問題（本書の対象外。描画の質感調整＝#875/#824）。

## 1. 先に区別する: #825 と #875 の役割
| | **#825（配置方法）** | **#875（描画。見た目は #824 の Pilot）** |
|---|---|---|
| 何を決めるか | 1 タップで**何が起きるか**: トッピング記録の数・座標、在庫の消費、採点（`minCount`・Reference Pieces）、UNDO の単位、最小距離（9%）、操作案内、保存 | 置かれた 1 件を**どう描くか**: 形・色・影・散布の分布（`placedVisuals/**` のみ） |
| 現状 | 1 タップ = 1 件（`PLACE_TOPPING` 1 回）。ルールは不変 | 1 件を、id で決まる 9〜11 片の散布として描く（箱 96px、場の半径 30） |
| 変更の扱い | **ルール変更**。Owner の決定表（#825 の S1）が必要 | 描画のみ。契約テスト（`gameReducer.sprinkleContract.test.ts`）で不変を固定 |
| 本書の案 | 案 D・E | 案 A・B・C |

「3 か所タップが 3 つの塊に見える」の根は、**1 タップ = 1 件**という #825 側の契約と、その 1 件を描く #875 側の領域の大きさの組み合わせ。#875 の範囲では、領域の見せ方しか変えられない（タップごとの塊そのものはなくせない）。

## 2. 現状の寸法（コード定数と HV 画像から）
- 1 タップの散布: 場の半径 30 単位＋片の張り出し 11 単位。箱 96px = 64 単位 → **約 1.5px/単位**、散布の広がりは**皿幅（約 300px）の約 2 割（半径で約 20.5%）**。
- Owner の 3 か所タップ（皿の座標 %）: (50,30)・(28,62)・(72,62)。相互の距離は **38.8%・38.8%・44.0%**。各散布の半径 20.5% では、隣り合う散布の縁の間に約 **−2〜+3% の隙間**（ほぼ接するか、わずかに離れる）。これが「3 つの塊」に見える直接の理由。
- 最小距離（9%）は、**近い**タップ同士なら散布が重なって 1 つの広がりに見える。離れたタップは別々の塊になる。
- 外周のタップは、皿の外へ出ないよう散布を中心側へ寄せる（上限 44 単位、最大 約 22%）。

## 4. 推奨
**案 A＋B（#875 内の描画のみ）を、まず 1 回試す。** 理由: (1) 今回の所見の原因（隣の散布が接する程度の広がり）に、最小の変更で直接効く／(2) ルール・契約・`PizzaStage` に触れない／(3) 副作用（外周のずれ・重さ）は HV で確認できる。

- 具体的な設計（案）: 場の半径 30→**34**（隣の散布の半径 22.5%×2＝45% で、Owner の 3 タップの距離 38.8〜44% を**覆う**）、片数 9〜11→**11〜12**、外側ほどまばらな勾配（格子の間隔を外側で広げる）、はぐれ欠片を **4〜5**、外周の寄せの上限 44→**52** 単位（外周でタップ位置から約 80px 離れて見える点は Result で開示。現行の 44 単位は約 66px）。
- 効果の見込み: Owner の 3 タップで隣の散布が重なり、画面中央が空いたままの「3 つの塊」から、広がりのある 1 つの散布へ。
- 副作用: 外周タップで散布がタップ位置から約 80px 離れて見える／片が増えて**やや重く濃く**見える／モッツァレラ上の重なり。
- **それでも塊が残る場合**: 案 D（別 Gate）を Owner に提示。案 E（#825）は、「振りかけ」の操作そのものを望む場合のみ。
