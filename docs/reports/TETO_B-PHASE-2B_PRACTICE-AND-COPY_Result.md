## 1. Q7：Pizza Select を報酬なしの「練習」にした

| 項目 | 内容 |
|---|---|
| ラウンドの種別 | `RoundKind` に `PRACTICE` を追加（`src/state/roundKind.ts`）。shop モードで、プレイヤーが自分で選んだレシピのラウンド（Pizza Select の `SELECT_RECIPE`、RESULT の「もう一度」= `RETRY_SAME_RECIPE`）が `PRACTICE` になる。legacy では一度も `PRACTICE` にならない（`GUIDED` のまま） |
| 注文 | FREE の Mito 注文（HOME「注文を受ける」・RESULT「次の注文へ」= `PLAY_AGAIN` → `BEGIN_PREPARE`）は `GUIDED` のまま。Phase 2a のループ（注文 → 調理 → 評価 → Pitz・評判 → 段階の進行）は変えていない |
| 報酬 | `REGISTER_TO_DEX` で、`PRACTICE` のときは Pitz（出来栄え・メニュー開発ボーナス）・手際ボーナス・評判を付けない。評価アダプタ（`serviceQuality.ts`）経由の付与は、練習では起きない |
| 調理 | `PRACTICE` は `GUIDED` と同じように調理する。完成判定（`completionPolicyForRound`）、工程ごとの下ごしらえ・蒸し・焼き付け・揚げの提示（`isCookingStepRound`）、生地・型の切り替え、FINISH・CUT は同じ |
| 図鑑 | 練習でも Dex の記録（BEST・作った回数）は従来どおり更新する。設計 Q7 で外すのは「報酬（Pitz・評判）」なので、記録は残した |
| R8 ジャーナル | 練習のラウンドを焼いたときは、`GUIDED` のジャーナルに `practice: true` を付ける。中断→復帰で完成させるときは `PRACTICE` として採点・登録するので、**注文ラウンドに化けない**（Pitz・評判なし）。復帰の通知に「練習のピザなので、Pitz・評判は入りません。」を出す |
| ジャーナルの互換 | 新しい `kind` は作らず、`GUIDED` に任意のフィールドを足した（Phase 2b より前のビルドでも読める）。`practice` が `true` 以外、または Free Cooking のジャーナルに付いているときは「corrupt」として保持し、推測では補わない |
| RESULT | 練習では「🧑‍🍳 練習のピザなので、Pitz・評判は入りません」を出す。「評判 +N」と「次の注文へ」は出さない（渡されていても出さない）。主ボタンは「もう一度練習する」 |

### Owner に確認をお願いしたい判断（1 点）

- **注文の RESULT から「もう一度つくる」を押した場合も、練習として扱いました。**
  - 理由: 「もう一度」はお客さんの注文ではなく、プレイヤーが自分で選んだレシピです。ここで報酬が出ると、同じレシピの繰り返しで評判を稼げてしまい、「Pizza Select ＝ 練習」と同じ抜け道になります
  - そのため、注文の RESULT では副ボタンの文言を「練習でもう一度つくる」にしました
  - **戻す場合は `startPreparingRecipe` の呼び出し 1 か所の変更で済みます**（`RETRY_SAME_RECIPE` だけ `GUIDED` に戻す）
