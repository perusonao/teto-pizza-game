## 1. 共通: 命名・状態機械の作法（T6 と揃える）

T6 の語彙に合わせる（C1・C2・C5）:
- イベント: `*_DOWN／*_MOVE／*_UP`（ジェスチャ）、`*_BUTTON`（代替）、`CANCEL`、`INVALIDATE`（前段が変わったら破棄）。

## 2. D-A（生地）— レビュー

### 2.1 原案の問題

原案の D-A「ひろげる＋／ちぢめる−」は**全周を等方に**数％ずつ動かす。これだと:
- **C2 に反する**: 自然なジェスチャ（またはタップ）は 8 点の輪郭を**方向ごと**に変えられ、不整形・楕円にできる。等方ボタンは常に整った円になり、結果の質が同じにならない。
- **採点・描画への影響**: `doughShape`（8 点）は Sauce Free Boundary（PR #66）や「生地の形に沿うソース」が読む。等方だと整った円で、後段が楽になる／変わる。

### 2.2 修正案 D-A′（推奨）: 方向を巡回する段階ボタン

- 8 方向のうち**現在の方向**を強調表示（輪郭上の点）。「**つぎの方向 →**」で巡回、「**＋**」（ひろげる）と「**−**」（ちぢめる）で**その 1 点だけ**を動かす。1 回の＋は既存の 1 タップの伸ばし量に相当する量（`applyStretchPoint` へ、現在の方向の外側の点を入力する形に変換）。
- これにより、ポインタのタップ（縁の点をタップ）と**同じ関数・同じ結果**になる（C2）。8 方向を順に＋すれば「縁の 8 点タップ」と同じ。
- 自然なジェスチャ（ドラッグ／タップ）は**そのまま残す**。ボタン列は任意の入口で、既定で出す／折りたたむかは Owner 判断（§6）。

### 2.3 状態機械（設計）

```ts
type DoughAltEvent =
  | { type: "DOUGH_DIR_NEXT" } | { type: "DOUGH_DIR_PREV" }
  | { type: "DOUGH_STEP_BUTTON"; delta: 1 | -1 }
  | { type: "CANCEL" } | { type: "INVALIDATE"; revision: number };
// state: { dir: 0..7; shape: DoughShape; stepsUsed: number }   // shape は applyStretchPoint の出力そのもの
// 出口: doughAltVisual(state) = { focusDir, shape }；確定は既存 COMMIT_DOUGH_STRETCH(shape)
```

不変条件: shape は既存の `applyStretchPoint` の閉域（`DOUGH_RADIUS` クランプ）にとどまる。＋／−は可逆（−は伸ばした分を戻す。下限は初期形）。方向の巡回は純粋で、保存しない。

## 3. S-A（ソース）— レビュー

### 3.1 原案の位置づけ

S-A「スタンプ」は、生地上のガイド点 5〜9 か所を**順にタップ**して一定量の円を置く。既存のポインタ操作は「押している間に出る（時間比例）」なので、S-A は**離散化**にあたる。

### 3.2 結果の同値性（C2）の検討

- 既存の確定アクション `COMMIT_SAUCE_DISPENSE(ingredientId, deposits)` は**deposit の配列を一括で受ける**（HV スターター `CookSearHvStarter.tsx` が `buildIdealMargheritaSauceFixture()` で同アクションを直接呼んでいる【コード実測】）。したがって **S-A は deposit を純粋関数で組み立てて同じアクションへ渡せる見込み**（reducer 変更なし）。ただし下記が未確認:
  - deposit の量・半径の分布（`SauceDispenseController` が時間・速度から決める量）を、固定量のスタンプで**どう同じ尺度にするか**。`sauceUsedTotal`／`sauceHeadroom`（上限）との整合。
  - `computeSauceMetrics`・Reference（`sauceDeposits` ベースの描画）・Sauce Free Boundary への影響。**スタンプが規則的すぎると、自然ジェスチャより高得点（または低得点）になりうる**。
- **等機会の原則（案）**: S-A の質は「どの点を選ぶか」で決まる（同じ点を二度押すと過剰、偏ると不足）。ガイド点は**ヒントであって正解ではない**（Anti-Oracle Contract に抵触しないよう、理想配置を示さない）。ガイド点の数・位置は Owner 判断。

### 3.3 状態機械（設計）

```ts
type SauceAltEvent =

  | { type: "SAUCE_UNSTAMP"; index: number }    // 戻す（任意）
  | { type: "CANCEL" } | { type: "INVALIDATE"; revision: number };
// state: { stamped: ReadonlySet<number>; deposits: SauceDeposit[] }  // deposits は純粋関数 buildStampDeposit(index, amount) の合成
// 出口: sauceAltVisual(state)（既存のヒートマップ描画に渡す形）；確定は既存 COMMIT_SAUCE_DISPENSE(ingredientId, deposits)
```

不変条件: 合計量は `sauceHeadroom` を超えない（超える押下は無視）。重複スタンプは**量を加算するか無視か**を Owner が決める（加算なら過剰が表現できる）。

## 4. C-A（CUT）— レビュー

### 4.1 原案の位置づけと最大の論点

C-A「2 点タップ」は、線の始点・終点を 2 回タップして直線の切り線を作る。**#418 の設計判断「CUT has no tap outcome」と直接衝突する**: 現在は誤タップが何も起こさないことが価値（`TRACE_MIN_LENGTH` 未満や縁かすりは破棄）。C-A を無条件に有効にすると、通常の指の接触で線が作られうる。

### 4.2 同値性（C2）は成立しやすい

CUT の確定は「見えている**直線**」（`buildTracedCutLine(g.cutPath)`）。2 点から作る直線は、スワイプの直線と**同じ表現**にできる見込み【コード実測: 直線で確定】。最小長（`TRACE_MIN_LENGTH`）・本数上限（`cutLimit`／`cutRequiredCount`）は同じ規則を適用する。

### 4.3 修正案 C-A′（推奨）: 明示的な「アーム」付き

- 「**📍 点で切る**」ボタン（ON 時のみ、タップが点指定になる。既定は OFF）。ON 中に 1 回目のタップ＝始点マーカー、2 回目＝終点で直線を提示し、「**切る**」で確定（または 2 回目で即確定）。「**やめる**」で解除。
- OFF の間は**現行どおり**（誤タップは無視）。#418 の価値を保つ。
- 縁近傍は縁へスナップ（スナップ半径 8 単位程度、暫定）。

### 4.4 状態機械（設計）

```ts
type CutAltEvent =

  | { type: "CUT_POINT"; x: number; y: number }     // 1回目=始点、2回目=終点
  | { type: "CUT_COMMIT" }                          // 「切る」
  | { type: "CANCEL" } | { type: "INVALIDATE"; revision: number };
// state: { armed: boolean; a: Pt | null; b: Pt | null }  // 出口: cutAltPreview(state) = 直線 | null；確定は既存 onAddCutLine(buildLine(a,b))
// 最小長未満・本数上限超過は何もしない（既存と同じ）
```
