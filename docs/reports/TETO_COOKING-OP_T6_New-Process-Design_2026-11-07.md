## 0. 結論

1. **推奨する次の新工程: 「包む（FOLD＋SEAL）」。** 実際の calzone／fugazzeta の作り方（具を半分に乗せ、生地を折って、縁を押さえて閉じる）に即し、iPhone 1 画面の「ドラッグ 1 回＋縁をなぞる 1 回」で成立する。FRY（泡の大きさ）・STEAM（殻が開く出来事）・炙り（長押し）・炒め（タップ時刻）・DRIZZLE（焼成後の線描画）と**入力語彙も時機も異なる**【推論】。
2. **Step 定義は main に既にあり、新規設計の大半は済んでいる。** `MakingStep` に `FOLD`／`SEAL`／`EDGE_FILL` が予約済みで、配線は 0【実測: `cookingProfiles.ts:71`、`makingStepLabels.ts:19`】。本書の仕事は、**配線の前に決める操作・採点・識別の論点と実装依存の整理**。
3. **レシピ数は増やさない工程。** 新食材 0 で解放が見込める行は `calzone`（BLOCKED_PRODUCT_DECISION）の 1 行のみで、他の ENCLOSE 行（fugazzeta／chicago-stuffed／a-caballo）は**厚い生地（DOUGH KIND 領域）が前提**、scacciata は新食材 1【実測】。「新しい遊び」が目的の工程で、数を増やす目的なら別の線（T5 の Batch 系）が効く。
4. **最大の実装リスクは 3 点:** (a) 折ると具が隠れるため Anti-Oracle／識別（結果は材料の集合で判定するため整合は取れる見込み）、(b) 円形前提の採点・CUT（`CUT_ELIGIBLE_RECIPE_IDS` は非円形の追加を禁止【実測】）、(c) HOT ファイル（`GameScreen.tsx`／`PizzaStage.tsx`／`gameReducer.ts`）の取り合い。

## 4. 推奨工程の設計 — 包む（FOLD＋SEAL）

### 4.1 プレイヤー体験（案、PROVISIONAL）

iPhone 縦 390×844 の 1 画面、新タブなし（タブ上限 6 は 11 レシピが使い切り、PREPARE の縦余白は 0px【先行: #773 比較書の監査】）。**既存の PREPARE 内、BAKE の直前**に FOLD→SEAL を置く（`cookingProfiles.ts` の step 順の記述どおり【先行】）。

| 段階 | 操作（片手・親指） | 実際の作業 | 完了条件 |
|---|---|---|---|
| 1. 具を半分に乗せる | 既存の TOPPING。有効領域が「折り線の片側の半円」に変わる（modifier、新操作ではない） | 生地の半分に具を置く | 既存の TOPPING の完了条件 |
| 2. 折る（FOLD） | 空いた半円の縁を指でつかみ、反対側へ**弧を描くドラッグ**。折り線をまたいで離すと閉じる方向にスナップ。途中で離すと戻る（失敗状態なし） | 生地を半分に折り返す | 重なり面積が閾値以上 |
| 3. 閉じる（SEAL） | 折った縁（半円の弧）を**指でなぞる**。なぞった長さ（連続性）が弧全体の何％か | 縁を押さえて貼り合わせる | 被覆率が閾値以上。**ゆっくり確実になぞれば満点**で、速さは問わない |
| 4. 焼く | 既存の BAKE | 蒸気穴は初版では省略（【推論】後の拡張） | ― |

- 失敗状態を作らない方針は STEAM・FRY・炙りと同じ。閉じ不足は「縁が開く焼き上がり」として BAKE の見た目に出す案（採点への出方は OD-F-3）。
- 既存の入力との差: ソース塗り＝長押し＋面を塗る、TOPPING＝トレイからドラッグして置く。FOLD は「生地そのものを動かす」ドラッグ、SEAL は「縁の線をなぞる」で、**成果物の形が変わる**のが他にない点【推論】。DRIZZLE の線描画と SEAL の縁なぞりはジェスチャが近いため、HV で「区別して感じる」ことを確認する項目に入れる（§7 HV-3）。
- 片手操作: 親指の届く範囲（画面下 2/3）に折り線と縁を収める。折り線は常に生地の中心を通る縦線（プレイヤーが選ばない）で、操作を単純化する案。

### 4.2 データと状態（設計メモ、実装しない）

| 項目 | 案 | 根拠 |
|---|---|---|
| 状態 | `fold: { progress, sealCoverage }` を一時状態として持ち、保存・Dex・在庫・スキーマは変更しない | PREP Phase 1 の `preparedIngredientIds?` と同方針【先行】 |
| 形 | 折り後は半円。**円形前提の採点と CUT は触れない**: 対象レシピは CUT 対象外のまま | `CUT_ELIGIBLE_RECIPE_IDS` の注記【実測】 |
| 識別（Discovery） | 結果は材料の集合で判定する Contract 2.1 のまま。包んだかどうかは識別の軸に**入れない**初版が安全 | 識別軸の追加は Anti-Oracle の Gate が重い【推論】 |

| 描画 | 折った生地と具が隠れる表現、閉じた縁、焼きの膨らみ | 描画の実装量が最大 |
