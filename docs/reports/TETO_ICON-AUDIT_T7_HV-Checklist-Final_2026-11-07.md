## 1. 事前（State Editor を使う場合のみ）— 安全確認

State Editor（`?dev=state`）は**その端末の Preview の保存（`teto-pizza-preview-save-v1`）を書き換える**。以下を**変更の前に**満たす。**満たせなければ State Editor を実行しない**（Owner 決定）。

### 1A. 優先: 別のブラウザコンテキストで行う

- [ ] iPhone Safari の**プライベートブラウズのタブ**など、**通常の Preview 保存と分離されたコンテキスト**を使う（保存が空のため、書き換えても Owner の進行に影響しない）。【分離されること自体は**実機で未検証**。Preview を開いてホームの進行（Dex／Pitz）が空であることを見て確認する】
- [ ] ホーム画面の Dex が 0/90、Pitz が初期値であることを確認（＝通常の進行が見えていない＝分離できている）。**進行が見えたら分離できていない**。1B へ。

### 1B. 分離できない場合: 復元を確認してから

State Editor は適用の直前に**元の保存を生のまま**（バイト単位）backup し、**書き込んだ後に読み戻して一致を確認**する（失敗したら適用しない。`apply.ts`・`backup.ts` のコメントより【コード確認】）。backup は保存とは別のキーに置かれ、Full Game Reset でも消えない。`original` は初回の適用でだけ作られ、以降は残る。

「復元できること」を**変更の前**に実機で証明する唯一の方法は、**空の保存に対する往復**:

- [ ] 1A のコンテキスト（空の保存）で一度、All Ingredients を適用 → 「バックアップ」タブで `original` が表示される（日時と「save なし（新規だった）」）→ 「復元する」（2 段階の確認）→ 「original から復元しました」→ 状態タブのセーブ表示が「セーブなし（新規）」に戻る。
- [ ] 上記ができたら、通常の保存のコンテキストでは**適用前に**状態タブの表示（Dex／所有／Pitz の数）を**メモ**し、適用後に「バックアップ」タブの `original` が「save あり（N 文字）」であることを確認、必要なら復元して**メモと一致**することを確認。
- [ ] **往復ができない・結果が一致しない・`original` が表示されない場合は、State Editor を実行しない。** 代替: Preview の実保存を使う材料（Pitz で買える範囲）で通常プレイするか、別端末／別プロファイルで行う（本書では未検討）。

後始末: 計測後、元の進行を戻すなら「バックアップ」→ `original` を「復元する」。

| 段階 | heat | 針（窓の中心を 68 と仮定した目安。**画面のゲージが実際の窓**） |
|---|---|---|
| H0 | 0 | 0（置いた直後〜焼成開始） |
| H1 | 0.8 | 約 54 |
| H2 | 1.0 | 約 68 |
| H3 | 1.6 | 約 87 |
| H4 | 2.0 | 100 |

- 針は 0→100 を約 3 秒（リハーサルの実測: 約 32 点／秒）。コマ送りが難しければ 2〜3 回録画する。

- 保存する静止画は、Owner が提出する分のみを `docs/reports/screenshots/<task-name>/` へ（動画は repo に commit しない）。
