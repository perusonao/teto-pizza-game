# Canvas モッツァレラ: 輪郭と表面の最終調整（#486 / PR #487）

基準 HEAD `e78c2dc`。Owner の iPhone 実機 HV: バッジ一致、モッツァレラ 4 個の表示を確認。旧版より輪郭が明瞭になり、白いぼかしが減り、乳白色も改善。ただし**輪郭に尖った腕が残り**、**表面が平面的で艶が不足**。カット後と画面復帰後の安全性は未確認。

## STEP 1: 原因調査（実装前の記録）

### 1. 三角形状・細長い突出部の原因
- 輪郭は極座標の半径 `R(θ) = 1 + lutH + lutT`（`cheesePool.ts`）。突出部（arm）は `lutT` の**ガウス形の盛り上がり**（`drawCandidate`: 振幅 0.3〜0.7、幅 σ = 0.3〜0.7 rad ≒ 17〜40°）。ガウス形は**先端が尖り、両側が凹んだ**形になる。半径方向の関数として定義しているので、「丸いローブ」ではなく「円錐状の腕」になる。
- 仕上げ（`buildGeometryFromBoundary`）で突出部を 1.3 倍に拡大（`OUTLINE_TONGUE_GAIN`）し、円形箱型平滑化（±8 bin を 2 回、標準偏差 約 7°）をかけるが、腕の幅（17〜40°）に対して狭く、先端が残る。
- 自然さの上限（`CHEESE_POOL_LIMITS.maxCurvature = 5.5`）は、円の 5.5 倍の曲率の尖りまで許す。生成時のフィルタが尖りを残す。

### 2. 輪郭の丸みが不足する原因
上と同じ。平滑化が弱く、腕の先端の曲率が高いまま。加えて、元の輪郭テスト（solidity 中央値 < 0.93、三つ葉の割合 < 0.7 など）が、丸い輪郭を「凸の楕円に近い」として許容しない設計だった（Issue #421 の最初の基準写真が、凹みの強い 0.76〜0.84 の溜まりだったため）。

### 3. 表面が平面的に見える原因
- 溶けた描画の厚みは「ほぼ一定のシート（0.5 ± 0.15）」を 2 回ぼかしたもので、法線がほぼ一定。`nh`（ハーフベクトルとの内積）が全面でほぼ同じ値になり、陰影も光沢も**一様**になる。
- 陰影の範囲は `[0.94, 1.03]` と狭く、光沢は `pow(nh, 18) * 2.2` の弱い加算のみ。**ほぼ白い面（約 240）は、明るくする余地が約 7 しかない**ため、加算の光沢はほとんど見えない。実測では、上位 3 % の明るさと中央値の差が 8.48（艶の項を消すと 8.57）で、**艶の項はほぼ効いていなかった**。

### 4. 艶を加えた場合のリスク
- 白飛び: `whiteClip`（輝度 > 246 の割合 ≤ 7 %）のテストが、天井を超える加算を禁止している。
- 人工的な光沢: 1 画素の硬いグリント（`pow(nh, 80)`）や、油の玉は、紙のような・ビニールのような質感になる（過去に実測済み）。
- 色の基準: 中心色の許容（~(238,234,218) ± 7）が、面全体を暗くしたり明るくしたりする調整を制限する。

## STEP 2: 実装変更（`renderWithGeometry` / `renderMeltedPixels` のみ）

A. **輪郭**: 溶けた描画のときだけ、半径テーブル `lut` を広い窓（±16 bin、3 回）の円形平滑化で丸め、`0.85 × fx` で混合する。腕の先端が丸まり、凹んだ両側が埋まる。ローブ・湾入・全体のアスペクトは残り、**円には戻さない**。焼成前（melt ≤ 0.3）は変更なし（`fx = 0`）。`fx` で連続的に混合するので、焼成途中で急変しない。

B. **表面**:
  - 厚みに、浅い中央の盛り上がり（`0.2 × smoothstep(1, 0.1, ρ)`）と、大きな低周波のうねり（0.5 倍に増加）を加え、「表面の一部に柔らかな厚み」を表す。傾斜は 4.5 → 5。
  - **艶はコントラストで見せる**: 艶（`gloss`）以外の面を最大 2.5 % 暗くし（`dim`）、ハイライト（幅の広い `pow(nh, 12)` ローブ）を、天井色 `(250, 247, 239)` に向けて移動させる。天井を超えないので白飛びしない。ハイライトは光源側（左上）に寄る（非対称）。油の玉・鏡面・1 画素のグリントは無し。
  - 面を少し暗くした分、`MILK` を (243, 239, 222) に調整して、中心色の基準（~(238,234,218) ± 7）に収めた。

C. **焼成**: 焼き色の処理は変更なし。焼成前の描画も変更なし。

D. **安全性**: `CheesePoolCanvas`（透明化検出、再描画、M1 フォールバック）は変更なし。カット後・結果画面の e2e（`canvas-mozzarella-optin-486`）は Chromium で通る。

## STEP 4: テスト・数値基準の変更と検出能力

### 元の基準を変えた箇所（最小限。理由付き）
輪郭を丸めると、solidity（面積 / 凸包面積）が必然的に上がる。元の基準は、Issue #421 の最初の基準写真（凹みの強い 0.76〜0.84 の溜まり）と、CSS プロトタイプ（凸の楕円 0.95〜1.0）の区別を前提にしていた。今回は Owner の指示（尖った腕を丸める）が直接の原因である。
| 変更 | 旧 | 新 | 備考 |
|---|---|---|---|
| solidity 中央値の上限（2 か所） | < 0.93 / < 0.94 | < 0.97 | 新分布: 中央値 0.957、p10 0.947、最大 0.971。旧分布: 中央値 0.908 |
| solidity p90 の上限 | < 0.95 | < 0.975 | 新: 0.965 |
| 「p5 < 0.9（凹みの広がり）」 | p5 < 0.9 | p95 − p5 > 0.01 | 凹みの広がりが「ゼロではない」ことは確認 |
| 「raw.solidity > done.solidity（溶けるほど不規則）」 | あり | `done.solidity < 0.985`（円ではない） | 丸めた溶け後の輪郭は、塊（ほぼ円）と同程度の solidity になるため |
| shadeSpread の上限（今回追加した自分のテスト） | < 1.12 | < 1.14 | 艶の意図的なコントラストを許容（元の上限は 1.3） |

**注意**: 新しい solidity 中央値 0.957 は、Issue #421 が「凸の楕円プロトタイプ（0.95〜1.0）」と呼んだ範囲に入る。形は非対称な不規則な溜まりで（アスペクト中央値 1.21、画像で確認）、楕円ではないが、solidity だけで「円ではない」ことは示せない。そのため、アスペクトの下限・尖りの指標・円の変異検出で補っている。

### 追加したテスト（4 件）
- 丸めた輪郭: `spikeShare` の p90 < 0.005（旧 0.006）、`slitFill` の p90 < 0.002（旧 0.003）、solidity 中央値 > 0.94 かつ < 0.97、アスペクト中央値 > 1.1。
- 光源側のハイライト: 輝度の上位 5 % の重心が左上に寄る（60 % 超）。内部に 1 画素のグリントがない（< 9）。白飛びしない（< 247）。
- 艶のコントラスト: 上位 3 % と中央値の差の平均 > 10（艶なし 8.6、あり 11.6）。
- （既存）焼成前のバイト一致（`dc1d20b` のハッシュ 7 件）は変更なしで通る。

## 残る課題
1. **艶**は控えめ（実機スケールで小さい差）。白い面で艶を見せる余地が小さく、これ以上は白飛び・人工感のリスクが高い。
2. 実物写真は 1 枚が基準（ネットワーク制限で追加できず）。
3. 輪郭のローブの数・位置は変えていない。solidity の数値基準は上げた（上記）。Owner の目視で「丸すぎる／足りない」を判断してほしい。丸め量は `OUTLINE_ROUND_*`（窓 16、3 回、混合 0.85）で、窓 22・混合 0.9 ならさらに丸く、窓 30 ならほぼ楕円になる（画像で確認済み）。
4. 複数ピースの接触、油の玉、縁のピンクの透けは未対応。
5. iPhone 実機・WebKit 画像の目視、カット後・画面復帰後の実機での安全性は未確認。
