### 1.1 遊びのルール（初期値。Owner 指示どおり確定値ではない）

| | あさり | ムール貝 |

| 開く進行値 | 0.26 / 0.50・0.51・0.52 / 0.80 | 0.30・0.31 / 0.55 / 0.85・0.86 |

- 進む速さ: 弱火 0.12 / 強火 0.22 /秒（V2 と同じ）。縮む速さ: 弱火 **0.32** / 強火 **1.2** /秒（V2 は 0.29 / 1.0）。

- 予兆: 開く 0.06 進行手前から貝が揺れて泡が出る（強火で約 0.27 秒前、弱火で約 0.5 秒前）。reduced-motion では揺れを止め、泡だけ残す。

- ★: ★★★＝5/5 かつ基準時間以内、★★＝5/5、★＝3〜4 個、なし＝0〜2 個。4 個以下が 5/5 と同じかそれ以上になることはない。
- 時間は**結果にだけ**表示（「★★★ 5.7秒」と「★3は6.0秒以内」）。プレイ中のカウントダウンはない。

## 2. 重要な検証の結果

### 2.1 弱火だけでは★★★にならない — **保証される**

最後の貝が弱火で開く時刻は、あさり 0.80 / 0.12 = 6.67 秒（> 6.0）、ムール貝 0.86 / 0.12 = 7.17 秒（> 6.8）。反応時間 0 でも届かない（単体テストで固定）。実ブラウザの自動プレイでも、弱火のみは全員 5/5・★★（下表）。

### 2.2 初心者・中級者・上級者（実ブラウザ・実時間・タッチ、390×844）

Chromium（`hasTouch`・`isMobile`）で、プレイヤー役が画面の状態を読み、貝が ready になってから**一定の反応時間**後にタップする。2 回のタップの間は 0.3 秒（指の移動）、火加減の切替もタップ 1 回。計画切替＝「ready と揺れている貝が合わせて 2 個以上なら弱火、それ以外は強火」。

| 種類 | 遊び方 | 初心者（反応 0.9 秒） | 中級者（0.6 秒） | 上級者（0.4 秒） |
|---|---|---|---|---|
| あさり | 弱火のみ | 5/5 ★★ 8.8 秒 | 5/5 ★★ 8.2 秒 | 5/5 ★★ 7.8 秒 |
| あさり | 強火のみ | 1/5 なし 5.8 秒 | 3/5 ★ 5.2 秒 | 4/5 ★ 4.8 秒 |
| あさり | **計画切替** | 4/5 ★ 6.4 秒 | **5/5 ★★★ 5.7 秒** | **5/5 ★★★ 5.3 秒** |
| ムール貝 | 弱火のみ | 5/5 ★★ 9.5 秒 | 5/5 ★★ 8.9 秒 | 5/5 ★★ 8.5 秒 |
| ムール貝 | 強火のみ | 1/5 なし 6.3 秒 | 4/5 ★ 5.7 秒 | 4/5 ★ 5.3 秒 |
| ムール貝 | **計画切替** | 4/5 ★ 7.3 秒 | **5/5 ★★★ 6.4 秒** | **5/5 ★★★ 6.0 秒** |

|---|---|---|---|---|---|

弱火のみはどの行も 5/5 100%・★★★ 0%。

### 2.3 火力切替が最高評価への有効な戦略になる — **なる（試作値 1.2 で）**

- 上級者でも、強火のみの ★★★ はあさり 21%・ムール貝 63%。計画切替なら 100%。中級者は計画切替で 60〜78%（実ブラウザでも両種類で ★★★）。
- 強火を 1.0 に戻すと、上級者は強火連打で 86〜96% 取れてしまい、切り替える理由が弱くなる。1.4 にすると、中級者の計画切替の ★★★ が 45〜64% まで下がる。**1.2 は「切替が最善」と「中級者が届く」の間**。

### 2.4 強火 0.71 秒の回収猶予は厳しすぎないか — **単独の貝なら許容、2〜3 個同時は意図して厳しい**

- 0.71 秒は「小」の貝だけ（あさり 1 個、ムール貝の最初のペア）。予兆を含めると、揺れ始めから縮むまで約 0.98 秒ある。反応 0.4〜0.6 秒のプレイヤーは単独の小をすべて強火のまま取れた（動画）。
- 反応 0.9 秒（初心者）は強火で小を取り逃がす。**初心者の安全な道は弱火（★★ 確約）**で、弱火の最短猶予は 2.66 秒ある。
- 強火で 3 個同時に開いたとき、3 個目は反応 + 0.6 秒が 0.88 秒以内に必要で、人には難しい。これが「揺れたら弱火」の理由になっている。
- **判断:** 自動プレイでは過度な難しさは見られなかった。新しい調整判断で止める条件（Owner 方針「動画で過度な難しさが見えたら止める」）には当たらないと考えるが、指で 0.71 秒が届くかは iPhone HV で Owner が判断する。

### 2.5 同時に開く 3 個を人間が見て判断できるか — **見た目は区別できる。ただし強火では予兆が短い**

- 待機中から 5 個の大きさ（小 0.80・中 1.04・大 1.28、段差 23%）と「小・中・大」の文字が見える。中が 3 個並ぶのを**始める前に**読める（`after-v3-390x844-idle.png`）。
- 開く直前に 3 個そろって揺れ、泡が出て、案内が「貝がいくつも揺れてる！一緒に開くよ」に変わる（`after-v3-390x844-trio-wobble.png`）。
- **注意（未解決）:** 強火の予兆は約 0.27 秒しかない。動画の中級者役（反応 0.6 秒）は、揺れを見てからの弱火が**開いた後**（2.55 秒、中は 2.27〜2.36 秒に開く）になったが、強火の猶予 0.88 秒の中で間に合い ★★★ だった。実際の人は、待機中の大きさから「中盤で弱火」と**先に計画する**ことが前提になる。予兆を長く（0.06 → 0.10 進行）してもモデルの成功率はほぼ変わらない（中級 ★★★ 55〜74%）ため、今回は変えていない。iPhone で「予兆が短すぎる」と感じた場合の第一の調整候補。

### 2.6 1 画面（390×844 / 360×800 / 390×664）— **維持**

E2E（Chromium 2 プロジェクト）で、待機・調理中（3 個が揺れている）・結果の 3 状態すべてで、scrollWidth / scrollHeight が画面以下、弱火・強火・やり直す ≥ 44px、貝の種類 ≥ 48px、貝のタップ領域 ≥ 44×44 で画面内、通知欄が画面内を確認。390×664 では鍋の絵が小さくなる（`after-v3-390x664-*.png`）が、タップ領域は 44px 以上を保つ。

### 2.7 V1 / V2・保存・本番への影響 — **なし**

- V1 / V2 の入口・ロジック・既存テストは変更なし（V1 / V2 の E2E・UI テストも再実行して成功）。`steamGameMode` の値が `v3` ちょうど 1 回のときだけ V3。
