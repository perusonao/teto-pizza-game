## 1. LAN 接続方式は V1 の安全条件を満たすか（再監査）

前回（Result §7.1）の I1「PC の `vite preview --host 0.0.0.0` を同じ Wi-Fi で iPhone から開く」を、V1 の 6 条件（#633 §11.3）に照らして再監査した。**結論: V1 の文言どおりには満たさない。** V1 は PC 上の Chromium（`127.0.0.1`）用の条件で、実機には別の条件が要る。**Owner が明示的に承認するまで、接続も公開もしない。**

| # | V1 の条件 | LAN 方式（I1） | 判定 |
|---|---|---|---|
| 1 | origin が `perusonao.github.io` でない | `http://<LAN の IP>:<port>` で別 origin | **満たす**（`seed.html` は github.io と https の公開ホストでは動かない） |
| 2 | 新規プロファイルで `localStorage` が空。本番・Preview の save を読まない | 実機の通常 Safari プロファイルを使う（新規プロファイルにできない）。ただし localStorage は origin 単位なので、この origin は空から始まり、`perusonao.github.io` の save には届かない | **文言どおりには満たさない／趣旨は満たす**（seed 前に「既存セーブ: なし」を目視） |
| 3 | `127.0.0.1` 以外への通信 0 件（Firebase 未構成、abort して件数記録） | iPhone→PC の通信は定義上 `127.0.0.1` ではなく、iPhone 側で通信件数を記録・遮断できない | **満たさない**。補完: Firebase 変数なしでビルド（アプリは未構成のとき Firebase を初期化しない）。PC の Chromium では、同じビルド系で図鑑→研究→仕上げ→発見まで通して外部通信 **0 件**だった（Result §5.7）。バンドルには Firebase SDK の文字列が含まれるが設定が無く、呼び出されない。外部への通信は PC 側サーバのアクセスログで確認する |
| 4 | 非公開（アップロード・デプロイなし、第三者に見えない） | アップロードは無い。ただし `--host 0.0.0.0` は**同じネットワークの誰にでも**未認証で配信する | **そのままでは満たさない**。補完は下の A1 |
| 5 | commit SHA・パッチ差分のハッシュを記録 | 可能（commit + `v1-literals.patch.txt` のハッシュ） | **満たす** |
| 6 | 確認できなければ開始・継続しない | 1・2 は目視、3 は機械確認できない | **一部のみ**（手動確認に置き換わる） |

### 代替・補完案（接続・公開は Owner 承認後）

| 案 | 内容 | V1 との関係 | 推奨 |
|---|---|---|---|
| **A1（推奨）V1-LAN: 2 台だけの私設ネットワーク** | PC を **iPhone のインターネット共有（パーソナルホットスポット）** に接続し、サーバを `--host 0.0.0.0` ではなく**そのホットスポット側の IP だけ**（例 `--host 172.20.10.x`）に束縛する。ネットワークには PC と iPhone の 2 台だけ。Firebase 変数なし・設定ファイルなし。アクセスログを残し、iPhone の IP 以外からの要求が無いことを記録。検証が終わったらサーバ停止・ディレクトリ削除 | 条件 4 を「2 台のみ・時間限定」で満たし、3 はログ＋Firebase 未構成で補完。**V1 の追補（V1-LAN）として Owner の承認が必要** | **推奨** |
| A2 | 公共の Wi-Fi や共有の家庭 LAN で `0.0.0.0` 配信 | 条件 4 を満たさない | **不可** |
| A3 | Mac の iOS シミュレータ + `127.0.0.1` | V1 の条件は満たす。ただし**実機ではない**ので HV の代替にならない（Chromium 録画と同じ扱い）。事前の動作確認にのみ使える | 補助のみ |
| A4 | 使い捨てホスティング（`github.io` 以外）へ Owner がアップロード | 条件 4（非公開）に反し、公開 URL が残る | 非推奨 |
| A5 | 別リポジトリの GitHub Pages | origin が `perusonao.github.io` のまま。**V3 として不採用済み** | 不可 |
| A6 | 共有 Preview・本番に ON ビルドを載せる | **本セッションの制限で禁止**。origin 共有で本番セーブに触れる | 不可 |

**V1-LAN の追補（Owner 承認済み・条件は LAN-HV §2）。承認を求めた文言（案）**: 「実機 HV に限り、条件 3（`127.0.0.1` 以外への通信 0 件）を『Firebase 未構成・サーバのアクセスログで iPhone の IP のみ・2 台だけのネットワーク』で、条件 4 を『アップロードなし・束縛 IP 限定・時間限定』で、条件 2 を『origin 分離＋seed 前の空確認』で置き換える」。承認が無ければ実機 HV は始めない。

## 3. iPhone 実機 HV の具体手順（E5 の見え方 + R8 を 1 回のセッションで）

前提: §1 の A1 は **Owner が安全条件付きで承認済み（2026-10-24）**。サーバの準備と条件の検証は `TETO_FIN-E5_LAN-HV-SERVER_Audit_2026-10-24.md`（以下 LAN-HV）。接続は Owner の操作で始まる。`TETO_FIN-E5_LAN-HV-SERVER_Audit_2026-10-24.md` §3 のビルド・サーバ手順（限定サーバ）で iPhone から開けること（ビルドする commit は同 §3 に従う。パッチは `kit/v1-literals.patch.txt` で、`main` afd1718 に `git apply --check` で当たることを確認済み。リテラルは `lateCatalog.ts` 32 行目）。**Result §7.1 の旧手順（`0.0.0.0`）は使わない。**承認が無ければ本節は実施しない。iPhone は Safari の**通常タブ**、**画面収録を開始**（通知の表示を後で確認できるように）。

**P. 準備（1 回）**
1. `seed.html` を開く。画面に origin（LAN／ホットスポットの IP）と「既存セーブ: なし」。違えば**中止**。
2. 「検証用セーブを書き込む」→「ゲームを開く」。**PREVIEW** バッジが出ること。
3. 記録: 機種・iOS・Safari かホーム画面か。ホームの Pitz（**999**）と、ピザ図鑑の件数。

**順序の原則（P2 指摘への対応）.** R8 の確認（R）は、**最初の FINISH（完成を押す前）で行う**。完成を押すと材料が消費され ikura が発見されて Pitz が加算されるため、その後では R-0 の初期値が成り立たない。R が済んでから、新しいラウンドで E-5（完成）を行う。

**E. E5 の見え方（研究 1 ラウンド目。完成は R の後）**
1. ピザ図鑑 →「研究中のピザ」→「このピザを研究する」（先頭で可）。タブが **生地 / ソース / チーズ / 具材 / 焼く / 仕上げ** の 6 つで 1 行に収まる（横スクロールなし）。
2. 生地を整える → ソースは何もせず「次へ」→ チーズで **クリームチーズ ×2** →「次へ」→ 具材で **サーモン ×3** →「焼く」→ ジャスト帯（65〜71）付近で取り出す。
3. 仕上げに進む（皿の名前は出ない）。**画面収録中であることを確認**。
4. 仕上げで **いくら ×2・大葉 ×1** を置く。**【O-12 判定】** いくらと大葉が生地の上で見分けられるか（Owner が実機で判定。基準は Owner の目。結果を「見える／見づらい／不可」で記録）。
5. **ここでは完成を押さず、下の R（R-1〜R-3）へ進む。** R の 4 回目の再起動が済んだ後、**新しいラウンド**で E-2〜E-4 をもう一度行い、完成を押す → 「いくらとサーモンのピザ を発見しました！」＋「後乗せ」。
